# 《生存日记》全端开发过程记录

> 本文从项目最初目标开始追溯，并从 2026-08-02 起作为每轮修改的固定交付持续更新。早期没有在每个节点保留运行截图的阶段只做事实回填，不补造截图。

## 项目目标

- 做一款开放式海岛生存游戏，不设置固定结局。
- 覆盖 Web、Android、iOS、macOS 与鸿蒙；鸿蒙当前只交付正式签名单机版。
- 支持引导 A / 自由 B，两种模式可切换，新玩家默认进入引导 A。
- 包含昼夜、天气、多地形、采集、合成、建造、背包、快捷栏、箱子、日记和存档。
- 联机版支持好友、聊天、岛屿邀请；鸿蒙联机版原方案包含“碰一碰”好友申请，但当前鸿蒙交付范围已收缩为单机版。
- 客户端发现 `manifest` 中版本或 build 更高时提示更新，下载到 Downloads 后调用系统安装器。
- 正式包放入 `website/api/apps`，同步更新 `manifest`、`client downloads` 与 `api/data/changelogs.json`。

## 阶段 1：概念与产品方向

最初方向是“玩家困在海岛上的生存日记”。经过多轮反馈，产品从少量固定地图、固定结局转向无固定终局的开放式生存：玩家持续探索、采集、建造和记录，不以通关动画结束。

关键决策：

- 游戏名沿用“生存日记”。
- 登录入口推荐通行证登录，下方提供灰色小字“本地游玩”；临时游玩等同本地存档。
- 新登录或首次下载默认使用引导 A，熟悉后可切换自由 B。
- 状态栏常驻，但数值必须由真实模拟驱动，不能永远显示 0 或静态值。

## 阶段 2：从展示页改成游戏

早期版本的问题集中在“像纯图片”“像工具而不像游戏”“地图小且重复”“角色与资源没有空间层次”。随后逐步加入：

- 可缩放、旋转、拖动的 2.5D 相机。
- 可探索区块、多地形、昼夜和雨雪。
- 资源节点、工具要求、耐久与采集产出。
- 绳索、石斧、石镐等分离配方，避免不同工具效果相同。
- 建筑放置、庇护所、床、营火、工作台、储物箱。
- 背包容量、快捷栏双向移动、可食用物品。
- 日记本、渐进式任务和不依赖固定结局的长期目标。

## 阶段 3：原生化与全端构建

Android 改为原生 Canvas 世界渲染与 Compose 游戏 HUD；Apple 端使用 SpriteKit + SwiftUI；鸿蒙使用 ArkUI 原生页面。Web 继续作为功能最完整且可直接访问的版本。

构建和分发目标包括：

- Android 正式签名 APK。
- iOS 与 macOS 原生工程/构建产物。
- 鸿蒙单机版正式签名 HAP。
- 下载中心正确展示名称、简介、版本、build、文件大小、SHA-256 与下载地址。

## 阶段 4：2026-08-02 生存循环、移动、存档与世界层次修复

### 用户反馈

- 游戏仍不够好玩。
- 生命、饥饿、口渴和体力之间没有巧妙关系。
- App 时间不流动，重开后无法稳定回到上次进度。
- 全端地图缺少地形与物品层次，实体看起来一样大。
- Web 角色走一段路会卡住，手机浏览器问题更多。

### 根因

- Web 把每一个隐藏区块的内边距都判断为不可行走，跨区块时会撞上看不见的阻挡带。
- 状态模拟没有在所有渲染循环中持续推进。
- 触摸移动阈值过低，轻微手抖会被误判成拖动；页面失焦后移动键可能未释放。
- 离屏实体仍参与绘制，且资源、建筑、玩家没有统一按脚底 Y 坐标排序。
- 部分原生端只有当前存档，没有损坏存档回退；玩家所在位置没有完整写回 Android 存档。

### 修改

- 30 分钟现实时间对应一个完整游戏日。
- 生命自然恢复条件改为：饱腹值至少 80、饮水值至少 70、体温正常、没有恶劣天气暴露且不在奔跑。
- 营养充足时体力恢复加速；中等营养正常恢复；低营养显著变慢；饥渴危机时停止恢复并扣生命。
- Web 区块改为连续可通行陆地，仍保留角落水域，避免角色走上水面。
- Web 增加视口裁剪、统一景深队列、资源尺寸分级、触摸抖动阈值和失焦清理。
- Web 当前存档损坏时回退到上一份成功存档。
- Android 在移动过程中把玩家格点位置写回存档，并在 App 退到后台时强制落盘。
- Apple 增加自动时钟、真实状态栏、后台落盘与上一份存档回退。
- Apple / 鸿蒙统一自动时钟、存档恢复和人物/建筑比例；一次“照片地面纹理拼块”方案因风格冲突被否决并撤回。

### 视觉方案复盘

真实引擎只提供渲染、输入和生命周期能力，不会自动产生统一美术。2026-08-02 的运行截图显示，当前 Web 把写实岛屿底图、商品式物品特写、卡通人物和木框 HUD 混在一起；资源尺寸过大，画面右侧还能看到未被世界覆盖的纯色背景。此问题被提升为美术系统问题，而不是继续微调阴影。

本轮先做的止损：默认镜头放大到能覆盖首屏、资源世界贴图缩小到环境物件比例、玩家增大到可读尺寸，保留统一的连续岛屿底图。新的跨端视觉基准图生成曾启动，但服务长时间无结果后终止，没有使用失败产物，也没有切换到需要额外密钥的降级模型。

### 验证

- Web：生存恢复、跨区块移动、资源尺寸、景深排序、触摸阈值、存档回退测试。
- Android：生存状态和 30 分钟昼夜单元测试；原生工程编译。
- Apple：生存规则、时钟、存档回退、实体尺寸测试。
- 鸿蒙：共享夹具一致性测试与 HAP 编译。

### 2026-08-03 “真正的游戏”全端重构设计

用户再次指出全端越来越不像真正的游戏。复盘确认问题不在是否使用真实引擎，而在世界被当作背景、资源像贴纸、角色比例过小、界面像工具面板，以及采集和建造缺少完整反馈链。

本轮先暂停代码修改，采用逐段确认方式重新锁定产品设计：

- 主镜头确定为可平滑移动和缩放的 2.5D 斜俯视。
- 美术确定为原创“写实手绘海岛”，参考成熟生存游戏的世界优先、克制 HUD 和发现式成长原则，但不复制具体皮肤。
- 确认探索、发现、采集、制作、建造、世界反馈和开放发展组成核心循环。
- 确认桌面与手机使用相同世界规则、不同输入和 HUD 布局；手机单独按安全区和拇指热区设计。
- 性能分为自动、流畅、均衡、精细四档；低配档只削减渲染成本，不删除玩法。鸿蒙中高配设备默认均衡或精细。
- 网页与下载中心新增“兼容模式”入口，避免使用带有贬义的“低级机”文案。
- 更新器继续保留，采用可收起进度，不再以置顶面板长期遮挡游戏。
