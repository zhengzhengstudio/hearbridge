# 铮铮眼镜响应式与跨端体验改版设计

## 目标

本阶段修复配镜流程在电脑、平板和手机上的布局漂移、控件换行、底栏遮挡和摄像头区域失衡问题，并让 Android 与 HarmonyOS 应用采用一致的产品结构。账户继续使用全局铮铮通行证，不为每个产品重复创建账号。

## Web 配镜流程

- 页面内容以 `1180px` 为桌面最大宽度，五个步骤始终在同一行；平板允许横向滚动，手机只突出当前步骤。
- 摄像头与参数区在宽屏采用约 `2:1` 布局，平板和手机改为上下排列。摄像头保持固定宽高比，不随提示文字或识别状态改变高度。
- 摄像头工具栏按“摄像头、采集、显示”分组，删除重复的切换按钮。按钮文本禁止拆字换行，并为状态标签预留稳定宽度。
- 字号调节只影响正文和结果，不改变工具栏、步骤条、按钮和底部导航的尺寸。
- 步骤操作栏留在当前内容区底部；全站产品导航保留固定位置，并通过安全区和页面底部留白避免互相覆盖。
- 合并重复的 onboarding 样式规则，建立单一响应式规则来源，避免后声明样式覆盖前面布局。

## Android

- 保留原生多页面和 CameraX + MediaPipe，不使用网页容器替代核心流程。
- 主页、配镜、心愿、聊天、我的使用稳定底部导航；子流程的上一步、保存和下一步位于内容区。
- 小屏按钮自动换行或横向滚动，禁止固定双列导致文字被挤成单字；相机预览使用设备尺寸和安全区计算高度。
- 通行证登录、临时用户和已保存数据沿用现有接口及缓存，不引入第二套账号。

## HarmonyOS

- 保留原生 ArkUI 页面和全局通行证，按 phone、tablet、2in1 宽度切换布局。
- 底部导航稳定在安全区内；大屏使用受约束的内容宽度，避免内容只挤在左侧或无限拉宽。
- 配镜步骤、相机控制和结果区采用独立组件，状态切换不重建整页，减少跳动。
- 本阶段不增加与布局无关的服务能力，也不改变上架包名和签名配置。

## 状态与容错

- 摄像头启动、切换、停止均有单一状态源；切换镜头时按钮保持原尺寸，只更新简短状态。
- 页面刷新后恢复当前步骤和已保存数据，但不会自动开启摄像头。
- 不支持摄像头或权限被拒绝时显示明确操作，不留下黑色空白区域。

## 验收标准

- 360px、390px、768px、1024px、1440px 和 2000px 宽度下无横向页面溢出。
- “切换前置”“网格”“眼镜”等文字不拆散、不漂移，按钮不因字号变化而重排。
- 五步流程、步骤操作栏和全站底栏不重叠；桌面首屏不出现大面积无意义空白。
- 摄像头在手机、平板和电脑上比例稳定，关闭后释放设备。
- Android 与 HarmonyOS 的主要页面均可到达，底部导航和子流程操作不互相遮挡。

## 验证

- Web 使用浏览器截图检查六档视口，并验证摄像头权限拒绝、开启、切换和停止状态。
- Android 执行构建和静态资源检查，并在小屏与平板配置检查导航和相机页。
- HarmonyOS 执行可用的 hvigor 构建或配置检查，验证 phone、tablet、2in1 声明不被破坏。
