# SpaceFight 无限战区跨端重构设计

## 目标

把 SpaceFight 从三个差异有限的俯视射击模式，升级为 Android、iOS、macOS、HarmonyOS 联网版和 HarmonyOS 单机版一致的完整飞行射击游戏。第一阶段必须解决游戏内信息看不清、缺少第一/第三人称、玩法单一，以及 HarmonyOS 手机横屏布局把开始按钮挤出屏幕的问题。

游戏始终由玩家驾驶舰船。世界不局限于黑色太空，而是在行星峡谷、云海风暴、海洋群岛、霓虹城市、冰原裂谷和废弃空间站之间连续生成。界面只借鉴现代战术游戏清楚、紧凑的信息组织，不复制任何第三方游戏的素材、品牌、配色或具体界面。

## 核心循环

1. 玩家在战备台选择任务、舰船、武器与模块。
2. 玩家进入当前无限战区，在连续区域中飞行和战斗。
3. 玩家完成任务目标，获得资源、熟练度和纪录。
4. 任务结束后可继续自由飞行、接取下一任务或返回战备台。
5. 资源用于舰体、武器和机动三条成长线；失败只结算本次任务，不清空永久进度。

第一阶段不引入账号依赖、基地建造、人物下舰或强制撤离。HarmonyOS 单机版继续保持无通行证、无网络权限和无远程更新请求。

## 六种任务

### 生存战

敌潮随时间升级，混合轻型、高速、轰炸和重装敌舰。目标是生存并刷新本机纪录，区域环境会改变敌人的进攻路线。

### 首领战

首领由护盾节点、武器舱和核心组成。玩家必须先破坏对应部位，再攻击核心；首领会按生命阶段切换攻击方式，不能只做高血量普通敌机。

### 护航战

玩家保护运输舰沿动态航线穿越区域。运输舰会绕开地形并在受损时降低速度，玩家需要清除拦截者和修复补给点。

### 据点防守

区域包含多个能源节点。玩家需要夺取、守住并在节点之间移动；敌方占领进度、友方控制进度和当前主目标必须持续可见。

### 限时歼灭

玩家在倒计时内击毁指定目标。连续命中和快速击毁形成连击并增加时间，攻击错误目标不增加奖励。

### 资源突袭

玩家扫描并收集散布在区域中的资源，同时应对守卫和拦截。达到任务额度即可完成，额外资源会提高收益但增加敌方压力。

## 镜头系统

战斗中提供两个可即时切换并记住选择的镜头：

- 第一人称：不显示玩家舰船，显示驾驶舱边框、准星、速度、姿态、锁定状态和必要仪表。镜头位于舰首，转向响应直接，但保留轻微阻尼以减少晕动。
- 第三人称：显示完整舰船、尾焰和附近地形，镜头位于舰尾上方并平滑追踪。高速转向时镜头延迟受上限约束，不能影响瞄准。

两种镜头使用同一套战斗状态、碰撞和武器逻辑，只改变投影、世界到屏幕的映射和显示层。切换镜头不能重置输入、任务、目标或暂停状态。

## 无限区域

世界由确定性种子和二维区域坐标生成。客户端只保留玩家附近的活动区域，离开范围的区域卸载；再次返回时根据种子恢复相同的地形骨架和已保存的关键状态。

六类首发环境分别定义地形约束和战斗规则：

- 行星峡谷：狭窄航道、岩柱和侧向伏击。
- 云海风暴：能见度和锁定距离降低，雷暴区造成能量干扰。
- 海洋群岛：低空飞行、岛屿遮挡和海面防御设施。
- 霓虹城市：高楼峡谷、移动航道和固定炮台。
- 冰原裂谷：强侧风、冰壁通道和低摩擦气流。
- 废弃空间站：外部结构、狭窄通道和失重残骸。

第一阶段先建立统一的区域接口、环境标识和任务兼容规则，并交付至少两类可连续切换的环境；其余环境按同一接口补齐，避免一次加入大量只有背景差异的空内容。

## 成长系统

永久进度仅保存在本机，分为三条互有取舍的成长线：

- 舰体：耐久、护盾和抗性；重装升级会降低机动。
- 武器：伤害、射速、能耗和特殊效果；高输出会增加能量压力。
- 机动：速度、转向和推进恢复；高机动会降低部分防护能力。

首版沿用五种武器并增加清楚的能耗、射程和用途说明。升级采用有限槽位，不允许所有属性同时堆满。存档包含版本、世界种子、成长、设置、纪录和已发现区域；读取失败时保留原文件并回退到安全默认状态。

## 战备界面

战备台使用高信息密度的原生布局：

- 左侧或紧凑模式顶部：六任务导航和选中状态。
- 中央：当前环境、舰船和区域预览。
- 右侧或紧凑模式中部：任务目标、危险、预计奖励和装备摘要。
- 底部安全区：固定的开始任务按钮，不随说明区域滚动。

选中项使用实心高对比状态，未选项使用清晰边线和灰白文字。关键正文必须位于近黑实体底板上，不能直接压在复杂战场图片上。页面不使用多层嵌套卡片，也不使用大量相似圆角块。

## 战斗 HUD

中心区域只保留准星、锁定和必要方向提示：

- 左上：舰体、护盾、能量和速度。
- 右上：任务名称、当前目标、进度、时间或控制点状态。
- 底部中央：五种武器和当前能耗。
- 两侧下方：触控移动和瞄准区域，仅在触控设备显示。
- 右侧安全区：镜头切换和暂停图标按钮。

目标、危险、友军使用固定语义颜色。所有文字、按钮和仪表需要达到可读对比度；战斗特效不得覆盖任务文字、触控区域或开始按钮。

## 响应式规则

### 手机横屏

任务列表改为单行横向选择器，任务说明区域可滚动，开始按钮固定在底部安全区。极窄窗口隐藏次要说明和装饰，仅保留任务、装备摘要和开始按钮。左右系统安全区、圆角和挖孔区域都必须纳入内边距。

### 手机竖屏

战备台可竖屏浏览，但启动战斗后请求横屏。若系统拒绝旋转，战斗 HUD 使用上下分区布局，不能溢出屏幕。

### 平板与二合一

采用三列战备布局和更宽 HUD 边距，信息密度增加但字体不按屏幕比例放大。窗口尺寸变化、分屏和折叠状态变化时即时重排。

HarmonyOS 不使用固定高度堆叠全部任务内容；根布局读取可用窗口尺寸，滚动区和固定操作区分离。Android 使用 WindowInsets，Apple 使用 safeAreaInsets，HarmonyOS 使用窗口安全区域和实际画布尺寸。

## 平台边界

### Android

保留原生 Activity、Canvas 和 60 Hz 本地模拟。拆分任务定义、镜头映射、区域生成和 HUD 布局计算，避免继续把所有逻辑压在单个绘制类中。LauncherX JDK 21 作为构建环境。

### Apple

iOS 和 macOS 共享 SpriteKit 战斗场景、任务规则和区域规则。iOS 提供触控布局，macOS 提供键鼠输入；两端共享镜头和任务状态，但使用各自原生战备外壳。

### HarmonyOS

联网版与单机版共享不含网络依赖的任务、镜头、区域和布局规则。单机工程不能导入网络模块。ArkUI 页面把战备台、固定操作区和战斗 HUD 拆成独立构建单元，画布只负责世界渲染。

## 数据流

输入层生成统一的移动、转向、开火、武器和镜头命令。任务控制器读取输入和当前区域，以固定时间步推进战斗；区域管理器根据玩家位置加载或卸载相邻区域；快照包含玩家、敌人、弹道、任务进度、区域和镜头状态。渲染器只读取快照，不直接修改任务状态。

本地存档在任务结算、升级、设置变化和应用进入后台时写入。写入采用临时文件和替换策略；失败时保留上一个有效存档并显示非阻塞提示。

## 错误与恢复

- 应用进入后台、窗口失焦或尺寸突变时立即暂停并清空持续输入。
- 资源加载失败时使用清楚的占位形状和错误提示，不显示空白战场。
- 区域生成异常时回退到安全训练区域，不结束整个存档。
- 存档版本不兼容时备份旧存档并执行显式迁移。
- 联网版连接失败只影响公开协作，不阻止六种本地任务。

## 测试与验收

- 六种任务必须拥有不同的目标状态和完成条件，不能只改变敌人数量。
- 第一和第三人称在任务中即时切换，输入、目标、生命和任务进度保持不变。
- Android、iOS、macOS、HarmonyOS 联网版和单机版包含同一组六任务名称与规则版本。
- HarmonyOS 在常见手机横屏、竖屏、平板和窄分屏尺寸下，开始按钮始终可见且可点击，页面无水平或垂直溢出。
- HUD 关键文字和按钮通过对比度检查，复杂背景下仍可读。
- 后台、失焦、暂停、旋转和镜头切换不会产生持续移动或误触开火。
- HarmonyOS 单机版继续通过无网络权限、无通行证、无 WebView 契约。
- 每个平台完成编译和安装包检查；有可用设备时补充真机输入、旋转和性能验证。

## 交付阶段

1. 基础可玩性：六任务、双镜头、高对比战备台与 HUD、HarmonyOS 响应式修复。
2. 无限区域：区域流式加载、两类完整环境、区域事件和任务兼容。
3. 内容与成长：补齐六类环境、三条成长线、存档迁移和长期纪录。
4. 发布：三端构建、签名、安装包、网站清单、更新日志和商店素材同步。
