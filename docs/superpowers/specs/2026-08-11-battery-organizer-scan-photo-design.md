# 电池收纳器扫码与照片功能设计

## 目标

为 HarmonyOS 联网版和单机版增加原生扫码添加与拍照留档能力，同时保持手机、平板和 2in1 可用。扫码支持商品条形码和电池收纳器记录二维码；照片首版每组电池限一张。

功能不得依赖内嵌网页。扫码、拍照取消或失败时，添加表单中已经填写的内容必须保留。

## 范围

本次包含：

- HarmonyOS 联网版与单机版的添加、编辑、详情和库存列表。
- Scan Kit 默认扫码界面与 CameraPicker 系统拍照界面。
- 商品条码匹配、用户条码预设和应用二维码导入。
- 照片本地保存；联网版登录后的照片上传、下载缓存与离线补传。
- 网站服务端的条码目录和电池照片接口。
- 旧电池数据、旧云端快照和不含媒体字段的客户端兼容。

本次不包含：

- 自定义相机预览或连续批量扫码。
- OCR 读取包装文字。
- 一组电池保存多张照片或将照片嵌入二维码。
- 单机版访问任何网络服务。

## 交互设计

### 添加与编辑

添加页标题下增加一行紧凑操作按钮：

- “扫码”：使用扫码 SVG 图标，打开类型选择菜单“商品条码”与“电池二维码”。
- “拍照”：使用相机 SVG 图标，拉起系统 CameraPicker。

按钮使用现有色彩令牌和 44vp 最小触控区域，不使用大胶囊。手机上并排显示，窄宽度时允许文字隐藏但保留可访问性说明；平板和 2in1 显示图标加文字。

拍照完成后在表单中显示 96vp 的方形缩略图，提供“重拍”和删除图标。编辑现有电池时显示本地缓存照片；只有远端照片时先显示加载状态，再显示缓存结果。

### 商品条码

扫码结果按以下顺序查找：

1. 当前账号的条码预设。
2. 应用内置的常见电池条码目录。
3. 联网版的服务器公共条码目录。

匹配成功后只填充名称、品牌、型号、化学类型、容量和电压，不覆盖用户已经填写的数量、最低库存、收纳位置、日期和备注。匹配结果显示在表单顶部，用户确认后再保存。

未匹配时将条码保存在表单中并提示用户补充信息。保存后可勾选“保存为我的条码预设”；单机版预设仅在本机保存，联网版预设随账号同步。

### 电池二维码

二维码采用版本化文本格式：

```text
zzbattery://import?v=1&data=<base64url-json>
```

数据只允许包含以下字段：`name`、`brand`、`type`、`chemistry`、`capacity`、`voltage`、`quantity`、`minimumQuantity`、`location`、`status`、`notes`、`barcode`。长度和数值范围必须校验，未知字段忽略。

导入时创建新的本地 ID，不接受二维码中的 ID、账号、令牌、照片地址或删除标记。识别后进入确认页，用户可以修改再保存。详情页增加“分享二维码”，生成同一格式的二维码；照片不包含在二维码中。

## 数据模型

`Battery` 增加可选字段，以保证旧数据可直接读取：

```text
barcode?: string
photoLocalUri?: string
photoRemoteId?: string
photoRemoteUrl?: string
photoUpdatedAt?: string
photoSyncState?: "local" | "pending" | "synced" | "failed"
```

本地照片复制到应用私有目录，并使用电池 ID 和随机后缀生成文件名。不得长期依赖 CameraPicker 返回的临时 URI。替换照片后先保留新文件，记录保存成功后再删除旧文件，防止失败造成照片丢失。

云端快照只保存远端媒体 ID、受控下载地址和更新时间，不保存另一台设备的本地 URI。合并记录时，照片采用 `photoUpdatedAt` 较新的版本；离线新增照片保持 `pending`，网络恢复和登录完成后自动补传。

## 原生能力

- 使用 `@hms.core.scan.scanBarcode` 的默认界面扫码，支持常见一维商品码和二维码。
- 使用 `@ohos.multimedia.cameraPicker` 的系统界面拍摄照片。
- 使用应用私有目录和文件 API 持久化拍照结果。
- 仅在用户点击按钮后拉起系统界面，不在启动时申请媒体权限。
- 设备不具备扫码或相机系统能力时隐藏对应入口，并提供清楚的不可用提示。

## 服务端接口

### 条码查询

`GET /api/battery-organizer/barcodes/:code`

- 公共目录可匿名查询，只返回电池预设字段。
- 条码只接受 6 至 32 位数字或受支持的 GS1 文本，拒绝路径字符和超长输入。
- 未找到返回 `404` JSON；客户端继续保留条码并允许手工填写。

### 照片

- `POST /api/battery-organizer/photos`：登录后上传一张图片，返回媒体 ID、受控 URL 和更新时间。
- `GET /api/battery-organizer/photos/:id`：仅记录所属账号可读取。
- `DELETE /api/battery-organizer/photos/:id`：仅所属账号可删除。

服务端只接受 JPEG、PNG 或 WebP，限制为 5 MB，使用服务端生成的文件名并校验实际文件类型。上传后移除不需要的 EXIF 元数据。删除电池或替换照片时清理旧媒体；清理失败进入后台重试，不阻塞电池文字数据保存。

## 同步与离线规则

- 联网版拍照后立即保存本地记录，不等待上传完成。
- 已登录且有网络时异步上传，完成后再合并最新云端快照并上传文字记录。
- 上传失败不撤销本地照片，状态显示为“等待同步”，手动刷新和下次启动都会重试。
- 未登录时创建的照片和条码记录保持本地；登录后按现有本地/云端合并规则上传，不删除本地新增记录。
- 单机版不包含上传代码、网络权限或远端 URL，只保存本地照片和条码预设。
- 删除带待上传照片的本地记录时，取消上传并删除本地文件；删除已同步照片时写入媒体删除任务。

## 错误处理与隐私

- 用户取消扫码或拍照视为正常操作，不显示错误弹窗。
- 无法识别、二维码格式错误、图片过大和服务不可用使用表单内状态提示。
- 日志不得记录二维码完整内容、照片路径、账号令牌或图片数据。
- 隐私政策补充相机、条码、照片用途、保存位置、云端同步条件和删除方式。
- 用户删除照片后，列表和详情立即更新；云端删除失败不恢复界面中的照片。

## 测试与验收

自动测试覆盖：

- 旧数据缺少新增字段时仍可加载。
- 已填写数量和位置不会被商品条码匹配覆盖。
- 未知条码可手工补全并保存为个人预设。
- 二维码字段白名单、长度限制、数值范围和新 ID 生成。
- 本地照片复制、替换、删除以及失败回滚。
- 联网照片 pending、补传、远端合并和删除任务。
- 单机版不声明 INTERNET 权限且不含上传入口。

真机验收覆盖手机、平板和 2in1 的深浅色模式：

- 商品条码、应用二维码、相册识码和取消操作。
- 拍照、预览、重拍、删除和应用重启后显示。
- 飞行模式拍照保存，恢复网络后自动补传。
- 两台设备登录同一账号后显示同一照片。
- 扫码和拍照过程中旋转或折叠设备后不崩溃、不丢表单内容。

## 发布

实现完成后分别提高联网版和单机版版本号，重新构建并使用各自正式 profile 签名 `.hap` 和 `.app`。更新本地下载备份、`api/apps` 安装包、客户端清单和面向用户的更新日志；更新日志不描述后台内部实现。
