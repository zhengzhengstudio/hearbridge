# 生存日记可玩核心、视觉与 Android 正式发布设计

日期：2026-07-28  
状态：已确认方向，等待规格复核  
关联规格：`2026-07-26-survival-diary-cross-platform-design.md`

## 1. 本轮目标

本轮把现有可移动、可采集的网页原型升级为能持续游玩的开放式海岛生存游戏，并交付可覆盖升级的 Android 正式签名安装包。重点解决以下问题：

- 游戏内容少，操作后没有持续目标或反馈。
- 日记本入口和日记内容缺失。
- 建造只是数值变化，没有真正生成并留在世界中的物体。
- 手机和桌面界面仍有遮挡、信息层级和触控反馈问题。
- 临时图标缺少产品辨识度。
- 下载中心读取的公开 `client-downloads.json` 与私有清单不同步。
- 当前 Android 包使用调试证书，不能作为正式发布包或稳定升级源。

本轮不引入固定结局、主线通关或方块式玩法。玩家可以无限期探索、建设、记录和改造营地。

## 2. 方案选择

采用“开放式生存建造闭环”，不采用单纯增加物品数量或以线性剧情为主的方案。

- 相比堆叠大量浅层物品，本方案优先保证每种资源都能进入制作、放置或生存消耗。
- 相比剧情日记方案，本方案让日记记录玩家真实产生的世界变化，不强制推动剧情。
- 相比重写引擎，本方案沿用现有原生 Canvas、HTML 和 CSS，逐步拆出物品、配方、建造物和日记数据模块，降低发布风险。

## 3. 核心游玩循环

玩家在“观察—采集—制作—放置—使用—记录”之间循环：

1. 移动和观察世界，发现资源点、可钓鱼水域和适合建造的位置。
2. 使用当前工具采集漂流木、纤维、石块、树枝、叶片、藤蔓、贝壳、鱼和淡水等资源。
3. 在随身制作或工作台中制作工具、绳索、建材、食物和设施。
4. 选择设施后进入放置模式，在地图显示半透明实体预览。
5. 预览通过边界、地形和碰撞检查后生成真实世界实体，并立即消耗材料。
6. 玩家使用设施恢复状态、存放物资、加工材料或改变营地生产能力。
7. 日记自动记录关键事实，玩家可补写自由文本；跨日后继续游玩，不触发结局。

体力、饮水和饱食随行动与时间变化。数值降低会影响移动或采集效率，但首版不使用突发死亡；耗尽时玩家在最近营地醒来并损失部分随身普通物资。

## 4. 首批内容范围

### 4.1 资源与物品

首批提供十二种可形成用途链的资源或物品：漂流木、树枝、纤维、藤蔓、石块、叶片、贝壳、淡水、生鱼、烤鱼、绳索和石斧。现有存档缺失字段时使用默认值迁移，不清空玩家已有库存。

### 4.2 配方

配方以数据声明输入、产出、制作位置、耗时和解锁条件。首批覆盖：绳索、石斧、收集淡水、烤鱼、篝火、简易庇护所、储物箱、集水器、工作台、晒鱼架、围墙和种植地。

制作失败时明确显示缺少的材料或所需设施；不会静默扣除材料。连续点击需要冷却或按钮禁用，避免重复制作。

### 4.3 可放置实体

首批八类世界实体为篝火、简易庇护所、储物箱、集水器、工作台、晒鱼架、围墙和种植地。每个实体保存：

- 唯一 ID、类型、坐标、旋转角度和所属岛屿区域。
- 碰撞范围、耐久、建造时间和创建日期。
- 实体自身状态，例如箱子库存、集水量、火焰燃料或种植物状态。

放置模式支持移动预览、90 度旋转、确认和取消。有效位置显示低饱和绿色描边，无效位置显示暖红描边并说明原因。确认后实体进入世界渲染、碰撞和存档；重新载入页面仍保留。拆除需要确认，返还一部分材料，正在使用或包含物资的实体不能直接拆除。

## 5. 日记本

日记本恢复为游戏 HUD 的稳定一级入口，桌面使用右侧纸页抽屉，手机使用全屏纸页层。它包含：

- 今日记录：时间、天气、到访区域、采集、制作、建造、状态变化和好友事件。
- 自由书写区：玩家可修改标题并写下文本，离开输入框自动保存。
- 历史页：按游戏日倒序浏览，不因新版本覆盖。
- 发现册：首次发现资源、设施或区域时生成独立条目。

自动记录只陈述实际发生的事件，不编造玩家感受。Kimi 日记草稿属于后续增强；接口失败或未配置 API Key 时，基础日记仍完整可用。日记默认本地私有。

## 6. 界面与视觉

沿用自然海岛与手绘日记的双重视觉，不采用紫蓝渐变、通用玻璃卡片或营销页式大标题。

- 世界采用清晰的 2.5D 俯视地形，保持当前连续地图和缩放能力。
- HUD 使用深海蓝灰半透明底、暖白文字和珊瑚橙单一强调色。
- 生存状态集中在顶部；快捷物品栏靠底；情境动作、日记和背包使用稳定位置。
- 手机 390×844 下所有必要按钮可见，触控目标不小于 44×44 CSS 像素，无页面级横向滚动。
- 桌面、平板和手机都提供按下、焦点、不可用、材料不足、保存中和保存失败状态。
- 放置物具有统一 2.5D 光照方向、接地阴影和可辨识轮廓，不使用表情符号充当最终美术。

## 7. 新应用图标

图标主体为一本被海水浸旧的深海蓝日记本，封面形成海岛地形切口，并嵌入小型罗盘刻线。整体为精致 2.5D 游戏图标，材料包含旧布、纸张边缘、盐渍和压印纹理；背景使用暖沙色到深海色的受控层次。

图标要求：

- 无文字、无现成商标、无细小场景堆叠。
- 轮廓在 48px 尺寸仍可识别。
- 1024×1024 母版保留安全边距，之后生成 Android 自适应前景、背景及常规 mipmap 尺寸。
- 网页 favicon、PWA 图标和 Android 图标使用同一视觉母版。

图像生成只负责母版探索与最终位图；尺寸裁切、锐化、安全区和 Android 资源输出通过确定性本地处理完成。

## 8. 状态、模块与存档

在现有代码中增加边界清晰的模块：

- `content`：物品、配方和建筑声明及查询。
- `crafting`：材料检查、原子扣除和产出。
- `placement`：预览、碰撞、旋转、确认、拆除和实体使用。
- `journal`：事实事件归并、玩家文本和历史页。
- `persistence`：存档版本、校验、迁移和写入失败恢复。

世界状态新增 `entities`、`journalEntries`、`discoveries`、`gameClock` 和 `saveSchemaVersion`。所有会改变库存或世界实体的操作先验证，再在一个状态事务中提交；失败不产生半成品。每次制作、放置、拆除和日记编辑后触发防抖保存，并保留最近一次可恢复快照。

旧存档迁移遵循“只补字段、不改现有坐标、不扣已有资源”。迁移失败时保存原始数据副本并创建可玩的默认存档，同时提示玩家导出诊断信息。

## 9. Android 正式签名

在 `/Users/ljg/Desktop/开发者/TRAE/Android证书` 创建“生存日记”独立 Android 发布密钥。该密钥不与 HarmonyOS 证书共用。

- 密钥库使用 PKCS#12 格式、RSA 3072 强度和 10,000 天有效期。
- 密钥库文件保存在指定目录；目录加入适当忽略规则，禁止提交私钥和密码。
- 密码生成后存入 macOS 钥匙串，构建时通过本机环境或安全读取方式提供，不写入 Gradle、脚本、日志或聊天。
- 输出 SHA-256 证书指纹、别名、有效期和离线备份说明。
- 正式 APK 使用 release 构建，不保留 `debuggable`，并通过 `apksigner verify --verbose --print-certs` 验证。
- 后续 Android 更新必须使用同一密钥；若密钥丢失，站外分发版本将无法原位升级。

本轮正式版包名保持 `cn.zhengzhengstudio.survivaldiary`。已有调试签名测试版无法直接覆盖安装正式版，测试用户需要卸载一次；从首个正式版开始保持签名连续。

## 10. 下载中心与发布清单

当前下载中心 `/api/downloads` 读取公开目录中的 `website/zhengzhengstudio.cn/api/apps/client-downloads.json`，而更新流程只改了 `website/api/apps/client-downloads.json`。本轮将两者纳入一个生成源，避免人工复制遗漏。

发布流程必须：

1. 构建并签名带版本号的 APK。
2. 生成 `latest` 副本。
3. 计算两份文件大小与 SHA-256，并验证签名一致。
4. 更新私有 manifest 与 client downloads。
5. 同步公开 manifest 与 client downloads 镜像。
6. 上传两个 APK；任一上传失败则不把版本标记为可下载。
7. 更新 `website/api/data/changelogs.json` 和公开更新日志镜像。
8. 重启服务后调用 `/api/downloads` 验证条目，再以 HTTP HEAD 和实际分段下载验证文件。
9. 在真实下载中心页面确认标题、图标、简介、版本、大小和按钮均正确。

清单中的 `signed`、`signing`、`storeReady` 和备注必须反映实际验证结果。调试签名文件从正式条目移除或明确降级为历史测试包。

## 11. 错误处理

- 材料不足：保留当前选择，列出缺少数量。
- 放置无效：不扣材料，显示碰撞、地形或边界原因。
- 保存失败：继续保留内存状态，显示未保存标记并自动重试。
- 图标生成不符合小尺寸识别：不进入应用包，重新调整单一视觉问题。
- 签名失败或证书信息不符：停止发布，不更新正式版清单。
- APK 上传中断：校验远端大小与哈希，不将不完整文件暴露到下载中心。
- 两份下载清单不一致：发布校验失败，阻止服务重启后的上线标记。

## 12. 测试与验收

### 12.1 自动测试

- 资源采集、制作成功、材料不足和原子扣除。
- 八类实体放置、碰撞、旋转、使用、拆除和存档恢复。
- 日记事实生成、自由文本保存、跨日历史和旧存档迁移。
- 体力、饮水、饱食变化与耗尽恢复。
- 390px、768px 和 1280px 布局契约。
- Android 包名、版本、正式签名、非调试标记、图标资源和离线资源。
- 私有与公开清单条目一致，下载文件大小和 SHA-256 一致。

### 12.2 手工验收路径

新玩家应能在手机或桌面完成：本地游玩 → 移动发现资源 → 采集材料 → 制作绳索和石斧 → 制作篝火 → 预览、旋转并放置篝火 → 使用篝火烤鱼 → 打开日记查看自动记录并补写一句话 → 刷新页面后确认库存、篝火和日记仍存在。

Android 验收包括：安装首个正式版 → 启动离线游戏 → 检查更新 → 下载更高 build → 校验文件 → 调用系统安装器 → 使用同一签名完成覆盖升级。

下载中心验收包括：搜索“生存日记”能看到正式 Android 条目；简介、图标、版本、大小和签名说明正确；版本号与 latest 两个链接均返回完整 APK；实际安装包证书指纹与发布记录一致。

## 13. 完成定义

只有同时满足以下条件，本轮才能标记完成：

- 核心手工验收路径在手机和桌面均通过。
- 日记、制作和八类可放置实体不是占位界面，刷新后仍保留。
- 新图标进入网页和 Android 正式包，并通过小尺寸检查。
- Android APK 使用新建独立发布密钥签名且验证通过。
- 两份 APK 均完整上传并能下载。
- `/api/downloads` 与真实下载中心页面均显示正式版。
- 两份 manifest、两份 client downloads 和更新日志一致。
- 不把尚未完成的 iOS、macOS 或 HarmonyOS 包标记为已交付。
