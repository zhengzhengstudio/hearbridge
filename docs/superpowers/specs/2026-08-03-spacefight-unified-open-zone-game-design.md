# SpaceFight 全端统一开放星区游戏设计

## 1. 目标

SpaceFight 将从“网页 Cocos 3D + 各 App 独立 2D 战斗壳”重构为一款共享同一游戏核心的开放星区作品。Web、Android、iOS、macOS 和 HarmonyOS 共用 Cocos Creator 3.8.8 中的战斗、地图、物品、任务、UI、声音和存档规则。原生 App 不加载网站，不使用 WebView。

设计目标不是同时堆出大量菜单和模式，而是先完成一条可重复游玩的纵向闭环：机库整备、开放星区飞行、空战、降落或登舰、第一人称枪战、收集物资、撤离结算和继续成长。

## 2. 当前问题

- 网页使用 Cocos 3D，Android 使用手写 Canvas，Apple 使用 SpriteKit，HarmonyOS 使用 ArkUI Canvas。各端只共享题材和文案，不共享战斗体验。
- 旧 App 以菜单、按钮和 HUD 为主，战场是独立 2D 投影，缺少真实空间、炮口、弹道、降落、步战和持续世界。
- 镜头输入和机体运动共用过多平滑与死区，导致鼠标与触屏扭头阻力大、瞄准落后。
- 原生端重复实现任务、操控和装备，一端修复不会自动作用到其他端。

## 3. 产品原则

1. 游戏先于功能壳：首屏直接呈现可操作机库与飞船，不将游戏藏在应用菜单后。
2. 同一规则跨端运行：平台差异只存在于输入、震动、系统登录、存储、更新和签名。
3. 单机不要求通行证；玩家市场、线上仓库与公开星区需要通行证。
4. 开放不等于空旷：程序生成用于连接地带、资源和动态事件，基地、舰船内部与重要任务区由人工设计。
5. 高配与低配保持玩法等价，只调整分辨率、LOD、阴影、特效、远景和同时呈现数量。

## 4. 核心循环

1. 在机库选择任务、星区、飞船预设与携带装备。
2. 驾驶飞船进入开放星区，自由导航、扫描、采集、运输或接受动态任务。
3. 通过空战突破巡逻、防空阵地、舰队或玩家封锁。
4. 降落到行星基地，或与空间站、残骸和大型舰船对接，切换为第一人称步战。
5. 搜集材料、蓝图、货币、任务物品与可交易装备，决定继续深入或撤离。
6. 返回基地后修理、出售、制造、装配、交易和解锁新星区。

## 5. 开放星区与地图

- 世界由多个大型开放星区组成，星区通过跃迁节点连接，不追求一开始就实现无限无缝宇宙。
- 每个星区至少包含太空航路、资源带、行星或卫星地表、可进入设施、动态事件和撤离节点。
- 不同地图拥有独立环境规则、敌对阵营、资源、市场需求与风险等级。
- 线上星区由持续公共基地和动态分片战区组成。首个多人里程碑以单区 8 人稳定同步为目标，在性能与服务端验证后再扩展。

## 6. 飞行与镜头

- 默认使用“街机响应 + 物理惯性”的混合方案。镜头和准星立即跟随鼠标或右侧滑动，机体以受限角加速度追随目标航向。
- 不对镜头本身叠加高阻尼。小幅输入立即生效，机体通过质量、侧滑、推力和辅助稳定体现重量。
- 默认开启飞控辅助。高级设置可逐项关闭自动回正、侧滑抑制和速度保持，获得漂移、反推和六自由度操作。
- 支持驾驶舱第一人称与机后第三人称；两种视角共享真实机头、炮口、弹道与命中判定。

## 7. 飞船武器与步战

### 飞船武器

- 武器包含实弹、激光、等离子、导弹和轨道炮。
- 炮口 Transform、弹速、散布、射程、后坐反馈、过热、装填、穿透、护盾与部件损伤全部参与模拟。
- HUD 同时显示视线准星、炮口汇聚点、目标提前量和导弹锁定进度，子弹不从屏幕中心凭空产生。

### 第一人称步战

- 玩家可在地表基地、空间站、残骸和大型舰船内离开飞船。
- 枪械支持腰射、瞄准、后坐力、换弹、弹道或命中扫描、护甲部位、工具与投掷物。
- 步战与空战共用任务、背包、伤害、阵营和结算规则，不作为无关的第二个小游戏。

## 8. 装备、套件与飞船自定义

- 外观套件默认为半固定作战套件：具有标志性外观、一个特色能力和预设工具槽。
- 达成熟练度或解锁对应蓝图后，玩家可拆分预设，自由搭配允许的外观、武器、工具和加成。
- 特色能力包括扫描、干扰、护盾偏转、维修无人机、EMP、诱饵、牵引和短距跃迁等。强项必须伴随重量、能源、散热、载荷或防护上的取舍。
- 飞船可更换基础框架、机翼、引擎、驾驶舱、装甲板、货舱与武器挂点。部件真实改变重量、推力、转向、护盾、散热、货舱和能源。
- 外观编辑支持涂装分区、材质、贴花、编号、灯光、尾焰与飞船命名。
- 玩家可一键使用官方预设，也可保存、分享和交易自定义蓝图。服务端校验挂点、碰撞体、属性与合法性。

## 9. 物资、货币与交易

- `信用点`：任务、出售物资和交易获得，用于维修、购买和常规制造。
- `材料`：矿物、舰船残骸、电子元件、生物样本等，具有地图、阵营和风险差异。
- `蓝图`：解锁飞船框架、武器、工具、套件和制造配方。
- 线上玩家可面对面交易，也可在基地市场挂单。物品、货币、手续费与交割由服务端托管，防止复制物品、双花和断线丢交易。
- 离线版使用本地价格变化和 NPC 订单，不进入玩家市场，不允许将本地物品带入线上仓库。

## 10. 失败与撤离

- 使用软撤离损失。飞船、已解锁武器与永久套件不因一次失败永久消失。
- 未放入保险仓的本局物资会掉落，在线战区可被其他玩家拾取。设备受损后需要修理。
- 低风险区的损失较低，高风险区具有更好掉落与更高损失，并明确显示进入风险。

## 11. UI 与交互

- 整体方向为“工业战术机库 + 驾驶舱战斗 HUD”，参考大型战术游戏的信息层级，不复制其界面、图标或美术资产。
- 机库中央为可操作 3D 飞船，左侧提供任务与星区，右侧显示当前套件，不使用通用应用的底部导航栏。
- 装配台以飞船全屏旋转预览为中心，挂点直接附着在机体上，边缘显示属性、能源、散热、重心和汇聚点。
- 星图为全屏缩放视图，直接显示资源、玩家活动、阵营、危险、市场价格与航线。
- 战斗 HUD 贴近安全区边缘，中央只保留准星、汇聚、提前量与威胁方向。
- 手机和平板只在横屏游玩。主操作常驻，次要信息使用标签或边缘面板切换，所有触控命中区计入刘海、圆角和手势安全区。
- 图标使用 SpaceFight 自有 SVG 图标集，不使用 emoji 或通用应用图标代替游戏视觉语言。

## 12. 输入与自定义

### 桌面

- 点击战场锁定鼠标，鼠标直接控制视线和期望航向。
- 键盘、鼠标、手柄按键与灵敏度可自定义。输入法组合、窗口失焦、暂停和视角切换必须释放持续输入。

### 手机和平板

- 左侧固定飞行杆，右侧相对滑动控制视线和航向，主武器、副武器、推进、工具与视角使用独立按钮。
- 允许调整按钮位置、大小、透明度、灵敏度、死区、Y 轴反转和左手布局。
- 步战使用独立的移动、视角、射击、瞄准、换弹、蹲伏、交互和工具配置，不直接套用飞船摇杆。

## 13. 声音与震动

- 引擎根据推力、速度、环境与受损状态连续变化。驾驶舱和第三人称使用不同的内外声场。
- 每类飞船武器和步战枪械拥有独立开火、机械动作、装填、过热和命中反馈。
- 导弹锁定、护盾破裂、装甲击穿、敌人方位与任务状态使用可区分的声音信号。
- 移动端震动按事件强度分层，不对持续推进长时间震动。
- 设置中独立管理音乐、环境、武器、语音、动态范围和震动强度，并支持完全关闭。

## 14. 性能与低配入口

- 渲染档位为自动、低配和高画质，内部独立管理动态分辨率、LOD、纹理、阴影、粒子、后处理、远景、物理频率与同时呈现数。
- HarmonyOS 默认高画质，不主动弹出降级提示，但保留设置中的手动切换。
- Android 默认高画质。首次运行在进入战斗前完成短暂检测；只有明显低于目标时才显示 `立即切换`、`暂时不` 和 `不再提示`，不在战斗中弹窗。
- Web 启动页提供明确的低配设备入口，选择后直接加载轻量资源包，不先下载高清资源。
- 低配基线以 Android/HarmonyOS 4 GB 内存设备 720p 30 FPS、老款 Intel Mac 720p 45 FPS、Web 低配 720p 30 FPS 为初始验收目标。实际最低系统与 GPU 清单由真机测试结果定稿。

## 15. 跨端技术架构

### 共享 Cocos 层

- 确定性模拟：飞行、步战、武器、伤害、物品、任务和结算。
- 展示层：3D 场景、角色、飞船、特效、相机、UI、声音和动画。
- 世界层：星区种子、人工地标、动态事件、资源点、阵营与刷新规则。
- 数据层：装备、蓝图、预设、地图、物资、价格和性能档位。

### 平台桥接层

- 通行证 API、更新检查、安全存储、文件系统、震动、系统权限、横屏全屏与平台生命周期。
- 平台桥接使用统一 TypeScript 接口，游戏规则不直接依赖 Kotlin、Swift 或 ArkTS 页面。
- 在退役旧原生战斗前，必须先对 Android、iOS、macOS 与 OpenHarmony/HarmonyOS 完成最小原生导出、真机启动和签名冒烟测试。

### 网络与服务端

- 单机模式直接驱动本地模拟。线上模式通过 WebSocket 发送输入命令与交互请求，客户端保留预测、插值和本地镜头。
- 服务端最终裁决位置、伤害、掉落、仓库、货币、制造和交易。
- 断线后进入有限重连窗口，服务端在窗口内保留战区状态。最终失败时按服务端记录结算，不由客户端自行判定成功撤离。

## 16. 下载、更新与设置

- 主站“我的”与“下载中心”继续由 `manifest.json` 和 `client-downloads.json` 提供平台、版本、构建号、大小、摘要、签名与系统要求。
- 应用只有在服务端版本高于当前构建时提示更新，不在游戏过程中强制打断。
- Web 的低配入口与 App 的画质设置使用相同档位定义，但各端独立保存用户选择。

## 17. 错误与恢复

- 资源加载失败时保留当前页面，显示重试、切换低配或返回机库，不进入只有 HUD 的空场景。
- 存档使用版本化结构、原子替换与上一份备份回退。本地存档不能直接覆盖线上仓库。
- 低帧率连续超过阈值时只在暂停或结算页建议降低画质，不在战斗中弹窗。
- 登录、更新和交易错误使用页内状态，不打开网页，不使用系统警告代替游戏 UI。

## 18. 实施分期

### 阶段 0：导出与风险基线

- 备份当前网页、Cocos 工程、原生 App、安装包与签名材料索引。
- 建立 Android、iOS、macOS 和 HarmonyOS 的最小 Cocos 原生导出，验证横屏、全屏、触控、震动、存储、启动速度与签名。
- 保留旧 App 作为回退基线，直到新工程通过首个可玩门槛。

### 阶段 1：单机纵向闭环

- 一个开放星区，包含太空航路、行星地表、一座可进入基地和一艘可登舰残骸。
- 完成混合飞行、真实飞船武器、降落/对接、第一人称步战、物资拾取、撤离与本地结算。
- 完成机库、星图、HUD、预设与基础自定义。
- Web 和四个原生平台使用同一 Cocos 内容通过可玩性与响应式验收。

### 阶段 2：线上协作与服务端经济

- 接入通行证、线上仓库、公开基地、星区分片、服务端伤害和掉落裁决。
- 完成面对面交易、基地市场、制造、维修、保险仓与断线重连。

### 阶段 3：地图与内容扩展

- 增加具有独立资源、阵营、环境规则、敌人和市场的新星区。
- 扩展飞船框架、枪械、工具、套件、蓝图、人工任务点与动态事件。

## 19. 首个可玩里程碑验收

- 玩家能在不登录的情况下完整游玩单机闭环，中途不加载网站。
- 鼠标或触屏输入立即改变镜头与期望航向，机体惯性不再表现为镜头迟钝。
- 第一/第三人称中的炮口、汇聚准星、弹道和命中点一致。
- 玩家能在飞船和第一人称角色之间完成一次可见的降落或对接过渡。
- 拾取的物资、保险仓、失败掉落、撤离结算和制造消耗可以通过自动测试重放。
- Android/HarmonyOS 的 4 GB 低配档达到 720p 30 FPS 目标，桌面与 Web 没有持续帧时间峰值。
- 手机横屏下机库、星图、装配、战斗、背包、暂停与结算均不越出安全区。
- 声音和震动事件与游戏状态对应，设置修改立即生效并可完全关闭。
- Android APK、iOS IPA、macOS DMG、HarmonyOS HAP/APP 与 Web 发布物通过启动、版本、更新、签名和安装验证。

## 20. 过程记录与证据

- 持续更新 `docs/spacefight/COCOS_REFACTOR_LOG.md`，历史起点保持为 Three.js 可核验基线。
- 每个里程碑记录用户反馈、根因、改动、自动测试、性能数据、原生构建、签名、安装包、Termux 同步与线上指纹。
- 真实截图统一存放到 `docs/spacefight/screenshots`，至少覆盖桌面、标准手机横屏、窄屏手机、平板和能运行的原生平台。
- 设计阶段不伪造运行截图；只有实际构建并运行的界面才进入验收记录。

## 21. 非目标

- 首个里程碑不实现单个无限无缝宇宙、大规模 MMO 同图、玩家永久建城或完整赛季运营。
- 不通过将网页嵌入 App 来伪造跨端一致。
- 不为了表面“内容多”保留无实际交互的飘浮建筑、空地图和无差异的武器。
- 不通过随意提升版本号代替可玩性、性能、构建与安装验收。
