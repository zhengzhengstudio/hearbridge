# 生存日记全端游戏设计

日期：2026-07-26

## 1. 项目目标

“生存日记”是一款全年龄、无固定结局的开放式海岛生存游戏。玩家以俯视角探索、采集、制作、建造和解谜，并在每天夜间记录日记。世界由持续生成的群岛、海域、洞穴和遗迹组成，玩家可长期探索、建设和联机。Kimi 驱动的“AI 岛屿导演”根据玩家当天的行为与日记生成次日叙事、建议、回忆和线索，但不直接控制资源、伤害、掉落或发展结果。

项目同时交付网页版、iOS、macOS、Android、HarmonyOS 联机版和 HarmonyOS 单机版。所有客户端采用平台原生实现，不使用 WebView 承载游戏。HarmonyOS 单机版用于鸿蒙应用市场，移除联网、账号、Kimi 和站外更新能力。

首发完全免费、无广告、无内购。内容为全年龄表现，不出现血腥、尸体或写实死亡。危险通过昏迷、营地受损、体力耗尽和被救援带回表现，动物只会逃走或被驱离。

项目参加 2026 年 B站 AI 创造公开赛。官方投稿与投币截止时间为 2026-08-20 23:59:59。参赛稿件为至少 1 分钟的横屏原创视频，使用官方活动标签，并展示真实可运行、可交互且以 AI 为核心的产品。

## 2. 交付范围与优先级

比赛首轮必须形成以下可玩闭环：

1. 单人无限持续的探索、建设、成长循环和本地存档。
2. 网页及五类原生客户端可运行版本。
3. Kimi AI 日记与本地规则引擎降级。
4. 2 至 4 人实时合作房间。
5. 铮铮通行证、临时身份和好友基础能力。
6. HarmonyOS 联机版碰一下加好友与碰一下岛屿邀请。
7. 正式构建、下载中心、版本清单、更新日志和商店素材。

在同一架构内继续完善公共岛屿、异步好友访问、非伤害型玩家竞赛和更大内容量。若比赛周期内需要取舍，先保证单人开放生存闭环、合作房间和 AI 日记的稳定与展示质量。

## 3. 全端架构

### 3.1 客户端

- Web：TypeScript 与 Canvas/WebGL。
- iOS：Swift 与 SpriteKit。
- macOS：Swift 与 SpriteKit，与 iOS 共享 Apple 规则层和资源结构。
- Android：Kotlin 与原生 Canvas/Compose。
- HarmonyOS 联机版：ArkTS 与 ArkUI Canvas。
- HarmonyOS 单机版：独立包名、独立工程和独立签名产物。

每个平台分别实现渲染、输入、音频、存档、权限、系统分享、推送和更新入口。所有实现共享以下规范化资源与协议：

- 物品、配方、建筑、动物、天气和剧情条件 JSON。
- 地图种子、伪随机数和生成规则。
- 科技、航海、营地、图鉴和岛屿秘密的长期里程碑条件。
- 存档结构、校验和版本迁移规则。
- WebSocket 消息结构与错误码。
- Kimi 请求摘要、响应结构和安全过滤规则。

### 3.2 服务端

服务端负责铮铮通行证、合作房间、公共岛屿、好友访问、排行榜、云存档、推送和 Kimi API 代理。实时联机采用服务器权威判定，客户端仅发送移动、采集、制作、建造和互动指令。服务器验证位置、冷却、配方、库存、岛屿权限和结果，降低作弊与跨端不同步风险。

### 3.3 一致性策略

各端从同一份内容数据生成或加载规则常量。关键模拟使用固定步长、固定世界种子与可复现随机序列。跨端黄金测试使用相同输入事件，比较资源、天气、建筑、剧情标记、区域生成和里程碑状态。

## 4. 核心玩法

一个游戏日由五个阶段组成：

1. 清晨制定计划，选择探索、食物、营地、科技或同伴关系重点。
2. 白天俯视角实时行动，包括移动、采集、制作、建造、钓鱼、种植、解谜和驱离动物。
3. 黄昏返回营地，分配食物、修理建筑并处理事件。
4. 夜间撰写日记。玩家可自由书写，也可使用 Kimi 生成草稿后编辑。
5. AI 岛屿导演读取结构化摘要，生成次日旁白、建议、回忆和候选线索。规则引擎决定实际可触发事件。

世界没有最终结局、通关画面、固定主线或游戏天数上限。完成发展路线后仍可继续探索、建设、联机和写日记。长期路线包括：

- 修复无线电，接收天气、漂流物和远方岛屿信号。
- 建造并升级船只，扩大可探索海域和运输能力。
- 建立可持续营地，发展种植、储水、能源和自动化。
- 破解遗迹与共同日记，逐步发现隐藏文明与岛屿历史。
- 完成生物、植物、地貌、食谱和制作图鉴。

地图使用世界种子按需生成连续群岛、海域、洞穴和遗迹区域。它不是方块世界，不提供逐方块挖掘。地形保持低多边形自然形态，资源以采集点和可交互对象存在。建筑使用可自由摆放、旋转和吸附的低多边形部件，不限制为固定蓝图。已探索区域、玩家建筑和生态变化持久保存，新版本可在未探索区域增加生物群系与内容而不破坏旧存档。

## 5. 视觉与交互

实时岛屿采用卡通低多边形风格，夜间日记采用手绘纸张、铅笔线稿与贴入式照片风格。颜色以海蓝、森林绿和珊瑚橙构成，不采用通用 AI 紫色渐变。

主游戏界面包含：

- 左上：日期、天气和当前目标。
- 顶部：体力、饱食、饮水和心情。
- 底部：六格快捷物品栏。
- 右侧：当前情境动作。
- 暂停页：地图、背包、配方、日记、好友和设置。

手机使用虚拟摇杆与情境动作键，桌面使用键鼠并支持手柄。所有平台支持色弱图标、字号调整、减少动态效果和温和提示。

登录入口的主按钮文字为“建议使用铮铮通行证登录”。下方提供“本地游玩”，并以灰色小字说明“临时身份和存档仅保存在本机”。临时房间昵称只保存在本机，无法跨设备找回存档或建立永久好友关系。

网站首页、游戏介绍和下载页使用非模板化的自然冒险视觉，采用不对称构图、真实游戏画面、统一圆角和单一强调色。营销页支持系统深浅色、减少动画和清晰的加载、空白与错误状态。游戏 HUD 与原生客户端分别遵循 Apple、Material 3 和 HarmonyOS 平台规范。

## 6. 身份、联机与好友

入口同时支持游客、本地游玩、铮铮通行证和临时房间昵称。跨端云存档、永久好友和公共身份要求铮铮通行证。

联网模式包括：

- 2 至 4 人合作房间，共建同一座岛。
- 公共岛屿，提供探索、交易和公共事件。
- 异步好友访问，可查看营地、日记和预设留言。
- 非伤害型竞赛，例如钓鱼、采集和限时建造。

好友系统包括：

- 按通行证 ID、昵称或邀请码查找。
- 申请、接受、拒绝、撤回、备注、删除、屏蔽和举报。
- 隐藏在线状态、所在岛屿和最近活动。
- 一键邀请加入合作房间，掉线后限时保留席位并支持重连。
- 异步访问营地、点赞日记和留下预设留言。
- 每日赠送一次普通物资，禁止赠送关键剧情物品。
- 共同冒险生成伙伴日记，每位玩家保留自己的视角。
- 好友上线、邀请、申请和新版本系统推送。

陌生人默认仅能使用预设短语、表情和地图标记。互为好友后可开启文字聊天，并经过敏感词过滤、频率限制、举报和监护设置。

## 7. HarmonyOS 碰一下

HarmonyOS 联机版提供：

- 碰一下加好友：双方进入碰一下页面，交换一次性好友申请令牌，双方确认后发送申请。
- 碰一下邀请上岛：仅在公共岛屿或明确允许邀请的非个人岛屿显示。私人岛、剧情岛或关闭邀请的房间不提供该动作。

令牌随机生成，60 秒过期且只能使用一次。服务端校验发送者、接收者、屏蔽关系和岛屿权限。令牌不包含账号密码、存档或 Kimi Key。接收方必须再次确认，服务端只保留最终操作记录。

实现优先使用 HarmonyOS 面向社交场景提供的 NFC 碰一碰能力，并结合 Share Kit 与 App Linking 传递受控邀请内容。HarmonyOS 单机版不包含碰一下、好友或岛屿邀请。

## 8. Kimi AI 与降级机制

默认由铮铮实验室服务端代理用户提供的 Kimi API Key。密钥不下发客户端。服务端执行用户额度、IP 与设备限流、响应格式校验、全年龄内容过滤和审计计数。

高级用户可填写自己的 Kimi Key。iOS/macOS 使用 Keychain，Android 使用加密存储，HarmonyOS 使用系统安全存储，Web 使用本机加密数据库。自带 Key 默认不上传铮铮服务器，设置页可删除并切回公共额度。

客户端仅发送完成叙事所需的结构化摘要：访问区域、事件、物资类别、建筑、同伴互动、玩家日记和剧情标记。不发送无关账号资料。

Kimi 超时、限额或断网时立即使用本地事件模板。违规输出被丢弃并允许一次重新生成。联机共同日记由服务器会话统一生成，避免多人重复计费。所有 AI 结果只形成叙事与候选事件，实际奖励、消耗和里程碑必须通过本地或服务端规则验证。

日记默认仅自己可见。好友可见与公共可见需要玩家分别主动确认。

## 9. 存档与异常处理

存档先写入本机事务文件，再异步同步云端。每个存档包含 schemaVersion、产品版本、构建号、地图种子、世界快照、事件日志尾部和校验值。

云端冲突时保留两个版本并让玩家选择，不静默覆盖。服务器短时中断时合作房间进入重连状态；超过恢复窗口后，服务端生成可下载的恢复快照，客户端保留本地恢复存档。

损坏存档先尝试最近的原子备份，再尝试事件日志重放。迁移失败时保留原始存档并提示导出诊断文件。

## 10. 版本更新与平台限制

存在更新的条件为：远端语义版本高于本机，或语义版本相同且远端 build 高于本机。客户端在启动、回到前台和手动检查时读取 manifest。用户允许通知后，服务端通过 APNs、FCM、华为 Push 和 Web Push 提醒新版本。

下载前验证文件大小和 SHA-256：

- Android：下载签名 APK 到系统 Downloads，校验后调用系统安装器。缺少未知来源安装授权时先打开系统设置。
- macOS：下载签名 DMG 到 `~/Downloads`，校验后调用系统打开。正式外部分发使用 Developer ID 签名与公证。
- iOS：测试阶段使用已授权设备、TestFlight 或合规 OTA 清单；商店版跳转 App Store 更新。普通应用不尝试绕过系统限制下载并安装任意 IPA。
- HarmonyOS 联机版：应用市场渠道跳转应用市场升级；直接分发测试渠道提供正式签名 HAP 及系统支持的安装入口。
- HarmonyOS 单机版：仅通过鸿蒙应用市场升级，不提供站外自更新。
- Web：Service Worker 检测资源版本并提示刷新，不打断当前游戏日。

## 11. 发布产物与下载中心

首发安装产物放入 `website/api/apps`：

- Android 正式签名 APK。
- iOS 可分发 IPA 与安装清单。
- macOS 签名 DMG。
- HarmonyOS 联机版正式签名 HAP 与 APP。
- HarmonyOS 单机版正式签名 HAP 与 APP。
- 各平台 latest 文件。
- 文件大小、SHA-256、构建时间和签名验证记录。

同步更新：

- `website/api/apps/manifest.json`
- `website/api/apps/client-downloads.json`
- 主站镜像 manifest 与 client downloads
- 下载中心简介、图标、版本、平台和单双机标签
- `website/api/data/changelogs.json`
- 主站 changelog 镜像

历史更新日志根据已有安装包、版本清单、文件日期、设计文档和提交记录补录。只写能够验证的事实，不推测或虚构旧更新。

## 12. 鸿蒙应用市场素材

单机版提交材料包括：

- 1024 × 1024 应用图标。
- 手机和平板横竖屏真实运行截图。
- 登录、探索、建造、AI 日记、好友和碰一下功能截图，其中联网能力只用于联机版宣传。
- 15 至 30 秒商店预览视频脚本。
- 应用名称、副标题、一句话简介、完整介绍和关键词。
- 隐私说明、权限用途、全年龄分级说明。
- 单机版与联机版差异说明和版本更新文案。

商店截图来自真实运行画面。没有可拍摄的鸿蒙实体设备时，可以另外制作明确标识为宣传合成图的写实手机场景图，但不将 AI 合成图冒充真实实拍。真正的实体设备照片需要连接可拍摄设备或提供设备照片。

## 13. 测试与发布门槛

发布前必须通过：

- 跨端固定种子黄金测试。
- 单机存档、云存档、冲突选择、迁移和断线恢复测试。
- 2 至 4 人移动、采集、建造、背包与共同日记同步测试。
- 公共岛、好友访问、屏蔽、举报与碰一下权限测试。
- Kimi 正常、超时、限额、违规输出和离线降级测试。
- version/build 比较、下载、文件大小、SHA-256 和安装入口测试。
- Android `apksigner`、Apple 系统签名工具和 HarmonyOS `hap-sign-tool` 验证。
- Web 桌面、手机和平板布局；原生端触控、键鼠、旋转、后台恢复和低内存测试。
- 下载中心逐项下载、简介、文件名、大小和校验值检查。

若证书、描述文件、设备授权或应用市场账号条件阻止正式签名，保留已验证的构建产物并报告精确阻塞。未签名包不得标记为正式版或 storeReady。

1. 固化共享规则数据、存档结构、协议和黄金测试向量。
2. 完成单人无限世界的首个稳定探索、建设、成长循环和 AI 日记。
3. 分别完成 Web、Apple、Android 与 HarmonyOS 原生渲染和输入。
4. 接入通行证、合作房间、好友和云存档。
5. 接入 HarmonyOS 碰一下、公共岛和异步好友访问。
6. 接入全端更新检测、推送、下载和合规安装入口。
7. 构建并验证正式安装包，更新下载中心与历史更新日志。
8. 生成鸿蒙商店素材和 B站参赛视频素材。
9. 完成全端验收并在官方截止时间前投稿。

## 15. 主要风险与控制

- 全原生多端开发量大：用统一数据、协议、测试向量和明确的比赛闭环控制偏差。
- HarmonyOS 碰一下能力存在设备与权限差异：提供 Share Kit 邀请和二维码邀请码作为兼容降级。
- AI 成本或稳定性波动：公共额度限流、自带 Key 和本地规则引擎三层降级。
- 多人状态复杂：服务器权威判定、事件编号、幂等操作和恢复快照。
- 商店审核限制：单机版彻底移除联网、自带 Key、站外更新和好友能力。
- 签名环境不完整：在构建前检查证书、Profile、设备授权和密码环境变量，禁止伪造正式签名状态。
