# SpaceFight 开放战区垂直切片设计

## 1. 目标

将当前“重复刷同类敌机”的波次模式，重构为一条可重复游玩的单机开放战区闭环：

> 据点准备 → 选择区域与目标 → 空中突入 → 战术着陆 → 地面搜战 → 继续深入或返航 → 结算、装配与成长

首个切片要证明三件事：操作直接可控，一局内持续产生选择，带回的物资会真正改变下一局。

## 2. 原创边界

- 可参考成熟战术游戏的信息层级、操作反馈和动效节奏。
- 不复制任何现有游戏的界面构图、图标、地图、角色、名称、数值、美术资产或标志性交互。
- SpaceFight 的核心识别为“轨道、低空、地表三层连片战区”与“飞船留场支援地面战”。

## 3. 玩法结构

### 3.1 一次出击

- 目标时长为 15–25 分钟，支持中途暂停与本地恢复。
- 玩家带着一个主目标进入，战区内生成 2–4 个可选事件。
- 完成主目标后可立即返航，或进入威胁和收益更高的区域。
- 失败时保留已装备物品、关键任务物和首次获得的稀有收藏；丢失未保险的当局战利品。

### 3.2 首个战区：黑潮缺口

战区为视觉连续、内部分区流送的三层结构：

1. **轨道带**：残骸回收场、导航阵列、远程空战和稀有资源。
2. **低空带**：运输线、防空节点、浮空工业据点和战术着陆点。
3. **地表带**：山谷道路、开采区、地下库区、前哨站与返航平台。

跨层飞行、进入云层、轨道电梯和据点通道用于隐藏流送，不出现返回主菜单的跳转。

### 3.3 动态事件

首个切片实装五类可组合事件：

- **运输线截击**：护送、拦截或跟踪运输舰，结果改变后续地面战的物资与敌人。
- **信号恢复**：定位并激活导航节点，解锁隐藏坐标。
- **据点突入**：先压制防空，再着陆进入内部库区搜索。
- **稀有资源涌现**：短时高收益区，同时吸引多方势力。
- **精英追猎**：可选的高风险目标，强调弱点、部位破坏和空地支援。

## 4. 战斗设计

### 4.1 节奏

采用“动态混合”：探索期间自由舒缓，普通遭遇短促且清晰，精英战强调掩体、弱点、部位破坏和工具配合。不通过单纯增加血量和数量制造难度。

### 4.2 空战与枪战联动

- 野外大部分平整区域可着陆，关键据点使用人工设计的安全着陆点。
- 着陆后飞船保留为世界实体，可存放物资、更换有限装备、撤回舰内和呼叫一次带冷却的火力支援。
- 防空系统、地面目标和返航路线互相影响，保证空战与枪战不是两个无关关卡。

### 4.3 敌人生态

首个切片使用两个原创人类势力和其自动化单位，异常生物作为低频战场变量。敌人必须有职责差异：

- 空中：截击、压制、爆破、支援与精英指挥。
- 地面：突击、侧翼、远程、盾卫、重装与固定炮塔。
- 同类单位不能全部直线追逐玩家；敌人使用距离带、侧翼点、退却、支援和可视预警来产生可读行为。

## 5. 成长、物资与装配

每局同时提供五类进展，但按来源和用途分类，避免无意义随机掉落：

- **装备战利品**：武器、舰体模块、护甲、工具和稀有改件。
- **制造材料**：矿物、电子组件、能源核心与异常样本。
- **货币与声望**：商店、势力任务、折扣、许可与后续选择。
- **情报与坐标**：隐藏据点、资源带、精英踪迹与事件触发条件。
- **外观收藏**：飞船涂装、角色服装、武器外观、徽记和据点陈设。

装配默认为半固定预设，保证新玩家可直接出击；进阶玩家可在舰体限制下自由调整武器挂点、引擎、护盾、战术工具、加成模块和外观。所有属性变化在模型挂点和实际战斗中可见。

## 6. 据点与新手引导

### 6.1 据点

- 据点可步行探索，包含机库、装配台、仓库、交易区、任务态势台和角色互动。
- 所有高频功能同时提供全局快捷入口，不强迫玩家反复跑路。
- 机库飞船使用实时 3D 模型，装配时镜头移向对应挂点，不使用静态宣传图假充游戏画面。

### 6.2 新手引导

- 首次启动提供约 3 分钟安全训练，覆盖移动、转向、瞄准、开火、锁定、拾取、着陆、离舰、装配和返航。
- 进入战区后只在首次出现新机制时给出情境提示。
- 提示根据键鼠、手柄或触屏自动更换按键图示，可跳过、可重播、不每次启动重复。

## 7. 操作与触屏反馈

### 7.1 操作预设

- 默认为直接响应：鼠标或右侧拖动立即影响镜头，飞船机身平滑跟随准星，不添加人为输入阻力。
- 额外提供重量惯性、高速街机与拟真飞行预设。
- 镜头灵敏度、机身跟随、死区、加速度、轴反转、辅助瞄准和键位可单独调整。

### 7.2 移动端摇杆

摇杆反馈是必须验收项：

- **触点反馈**：按下时基座在手指起点显现，握柄缩放 96%，无延迟跟随。
- **方向反馈**：指向刻度和方向弧显示当前输入，不用大面积发光。
- **死区反馈**：越过死区边界时产生一次轻震；死区内明确显示为中性状态。
- **行程反馈**：达到 75% 与 100% 行程时有可辨识的刻度和可选轻震，助推触发有独立反馈。
- **回中反馈**：松手后只有视觉握柄用 90–120ms 回中，逻辑输入立即清零，避免“摇杆还在飘”。
- **触摸所有权**：每个摇杆绑定首个有效指针 ID，指针离开、取消、切出应用或打开暂停时必须释放，防止卡住输入。
- **可访问性**：震动强度、视觉反馈强度、动态/固定摇杆、大小、位置和透明度可调，设置中可完全关闭震动。

### 7.3 键鼠与手柄

- 电脑端默认不显示摇杆，鼠标点击战场后锁定指针，`Esc` 释放并暂停。
- 视角、射击、移动不依赖文本输入焦点，进入战场时主动失焦输入框，避免输入法抢键。
- 手柄提供独立死区、曲线、振动与键位设置。

## 8. 全端原生 UI 与动画

### 8.1 实现边界

- Android、HarmonyOS、iOS 和 macOS 直接运行 Cocos 游戏，不加载网站，不使用 WebView 实现主界面、装配台或战斗 HUD。
- 机库和战场是实时 3D 场景；界面使用 Cocos UI 节点、字体、图标精灵、九宫格组件、遮罩和动画实现。
- 更新器、存储权限、系统振动、文件选择和平台弹窗通过 Kotlin、ArkTS 和 Swift 桥接实现。

### 8.2 组件视觉

使用已确认的克制轻工业组件基准：

- 深灰哑光底、高对比浅色内容、低饱和薄荷绿活动态、琥珀色仅用于主命令、红色仅用于危险。
- 单独定义主按钮、次按钮、图标按钮、分段选择、分页、状态条、任务条、警告、装配挂点、滑杆、开关、复选框和触屏控件。
- 不使用网页卡片阵列、大面积渐变、玻璃拟态、装饰性发光、过多六边形、螺丝和无意义切角。
- 字段与本地化文字始终由引擎渲染，不烘焙进按钮图片。

### 8.3 动画

- 普通按压与选中反馈 80–140ms，面板切换 160–260ms。
- 装配切换时镜头移向对应飞船挂点，属性变化与实体模块替换同步。
- 战区情报通过局部扫描逐层显示，不使用大幅弹跳或循环装饰动画。
- “出击”是统一主命令用语，不使用“部署”。

### 8.4 响应式

- 全端仅横屏游玩，使用安全区、锚点、最小点按尺寸和三档界面密度，不等比压缩 1920×1080 界面。
- 手机收纳为底部分页和情境操作，平板使用双栏，桌面使用高密度边缘工具。
- 所有浮层必须在刘海、圆角和系统手势区内重新排布，不得超出视口。

## 9. 技术架构

当前 `CombatSimulation` 同时承担飞行、敌人、弹丸、掉落和波次任务，`CombatBootstrap` 同时承担启动、资源、场景、输入和 UI 桥接。垂直切片将在不更改定长模拟核心的前提下分离责任：

- `ExpeditionDirector`：出击阶段、事件选择、风险升级与返航状态。
- `EnemyBehaviorSystem`：敌人角色、距离带、目标选择、预警和群体行为。
- `LootAndCargoSystem`：掉落表、货舱、保险、拾取和返航结算。
- `LandingAndSupportSystem`：着陆条件、飞船留场、离舰、撤回与火力支援。
- `WorldRegionStreamer`：三层区域状态、资源预取、质量档与降级资产。
- `NativeGameHud`：使用统一状态模型渲染键鼠、手柄和触屏 HUD，不反向控制模拟逻辑。
- `PlatformFeedbackBridge`：封装振动、音频、安全区和平台生命周期，在不支持时安静降级。

数据流为：

> 输入适配器 → 标准化命令 → 定长模拟与系统 → 不可变快照 → 3D 表现 / HUD / 音频 / 震动 / 本地存档

单机版不要求通行证、网络连接或网站登录。模拟快照和事件接口保持可序列化，为后续 WebSocket 多人同步留出边界，但首个切片不实装多人。

## 10. 失败恢复与兼容

- 任何必要舰船、地形或 UI 资产超时时，必须使用本地降级资产进入战场，不得因单个 GLB 导致 App 永久卡在 Cocos 启动页。
- 场景启动使用可见阶段和有上限的重试；失败时显示本地诊断编号和“使用兼容模式重试”。
- 鸿蒙默认高配；安卓根据 GPU、内存和首帧时间自动识别。低于建议档时弹出一次低配建议，支持“切换”、“暂不”和“不再提示”。
- 低配模式只减少植被、远景、粒子、阴影、残骸密度和同屏敌人表现，不删除任务、掉落或成长系统。

## 11. 测试与验收

### 11.1 自动测试

- 定长模拟在同种子和命令序列下产生一致快照。
- 五类事件可完成、失败、放弃并进入正确结算。
- 保险、货舱、结算和失败损失符合规则。
- 不同敌人职责具有可区分的距离、移动和开火行为。
- 触摸取消、切后台、暂停和多指切换后不存在粘滞摇杆输入。
- 无震动设备、缺失模型、低内存档和断网状态都可进入单机战场。

### 11.2 实机验收

- Android 和 HarmonyOS release 包在真机上冷启动进入据点，完成训练并进入战场。
- 手机横屏下开始、摇杆、开火、暂停、出击与返航按钮不超出安全区。
- 摇杆对角线输入满幅时不降低速度，松手后一帧内逻辑归零，反馈震动不连续轰鸣。
- 鼠标锁定、视角转动、开火和文本输入法切换不互相抢占。
- 高低画质分别进行不少于 10 分钟的战场循环，无无敌卡死、敌人不受伤、场景穿透和资源无限增长。

### 11.3 视觉验收

- 保存 1920×1080 桌面、常见横屏手机与平板截图，检查安全区、字号、对比度、遮挡和点按区。
- 动态机库、装配挂点、战斗 HUD、着陆、地面战和返航结算均必须有对应过程截图。
- UI 不得通过展示静态概念图冒充实时游戏画面。

## 12. 版本、构建与记录

- 每个可交付实施批次必须同时提升版本号和 build 号，不随意使用 `1.0`。
- 本轮实施从当前 `0.10.22 build 41` 之后递增，具体版本由实施计划按交付批次划分。
- 每次构建保存日志、签名检查、包哈希、实机结果和截图链接，并更新 `docs/spacefight/COCOS_REFACTOR_LOG.md`。
- 发布包复制到 `website/api/apps` 的对应下载目录，更新 `manifest.json` 和下载中心。
- 如果更改 `website` 的非敏感用户功能，同步更新 `website/api/data` 中的更新日志。

## 13. 首个垂直切片的完成标准

一名新玩家可以在 Android、HarmonyOS 或网页版中：

1. 通过 3 分钟训练理解两种战斗方式和返航目标。
2. 从可用的原生据点界面进入黑潮缺口。
3. 完成至少一次空战、战术着陆、地面枪战、战利品搜索和飞船支援。
4. 在两个可选事件中至少做出一次风险/收益决策。
5. 成功返航，将战利品存入仓库，并在装配台中安装一个会实际改变下一局战斗的模块。
6. 在全过程中不遇到卡在 Cocos、鼠标无法转向、摇杆粘滞、按钮超出屏幕或必要模型超时导致无法游玩。
