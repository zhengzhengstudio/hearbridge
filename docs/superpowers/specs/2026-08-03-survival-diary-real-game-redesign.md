# 《生存日记》全端“真正的游戏”重构设计

日期：2026-08-03  
状态：设计已逐段确认，等待最终审阅  
范围：Web、Android、iOS、macOS、鸿蒙单机版，以及为联机版保留的交互结构

## 1. 目标

把当前“背景地图上叠加工具面板”的产品，重构为一款世界优先、操作有反馈、成长可持续的开放式 2.5D 海岛生存游戏。游戏不设置固定结局；玩家通过探索、发现、采集、制作、建造、耕种、航行和联机生活长期改变世界。

完成标准不是更换一套 UI 皮肤，而是：玩家进入后首先注意到可操作的世界；资源、人物和建筑有可信比例与空间关系；每项常用操作在场景中发生并产生动画、声音、掉落和状态变化。

## 2. 视觉方向

采用原创“写实手绘海岛”风格：自然比例、细腻材质、克制色彩、明确轮廓，不追求照片级写实，也不模仿现有游戏的角色或界面皮肤。

- 主镜头为约 45 度的 2.5D 斜俯视，可平滑缩放和移动。
- 世界是连续区域，不使用可以一眼看完的微缩岛屿。
- 沙滩、浅海、红树林、淡水河、密林、岩地和高地自然相连。
- 前景植被、活动平面和远景雾层构成明确纵深；实体按脚底位置排序并正确遮挡。
- 人物、树木、灌木、矿脉、小型采集物和建筑使用不同尺寸层级，不允许同尺寸贴图堆叠。
- 水面以岸线深度、浪花、湿沙和不可通行反馈表明边界，不用隐形墙掩盖。
- 昼夜、云影、风、雨雪、积水、火光与湿润材质共同改变环境，而不是只替换滤镜。

## 3. 核心生存循环

### 3.1 分钟级循环

观察环境 → 靠近目标 → 选择正确工具 → 完成有动作反馈的采集或交互 → 拾取有空间位置的掉落物 → 制作或加工 → 放置并使用设施 → 世界状态发生可保存变化。

砍树需要斧，采矿需要镐，挖掘需要铲，切割和剥取需要刀。工具拥有用途、速度、耐久和命中表现，石斧不能再等同石镐。

### 3.2 小时级循环

寻找淡水与食物、建立火源和庇护、制作箱子与床、应对昼夜和天气、探索新生态区、发现材料并解锁工作站和配方。

### 3.3 长期循环

扩建营地、种植与养殖、加工高阶材料、修建码头与船只、探索更远岛屿、收集图鉴和日记、与好友建设公共岛。任务用于介绍系统和记录阶段，不形成固定结局。

### 3.4 生存数值关系

- 饱腹与口渴处于良好区间、体温正常且没有恶劣暴露时，生命缓慢恢复。
- 高品质食物、睡眠、火堆和完整庇护提高恢复效率。
- 奔跑、负重、寒冷、淋雨、受伤和疾病改变体力消耗或阻断恢复。
- 饥饿和脱水进入危险区后先削弱体力恢复，再持续损失生命。
- 所有状态均由实际模拟驱动，常驻状态栏不得长期显示静态值或全为零。

## 4. 发现、配方与世界反馈

- 未发现的材料和配方不展示完整实体列表，只显示模糊线索或日记空位。
- 首次拾取材料、研究样本或建立工作站会解锁相关配方簇。
- 配方必须检查材料、工具、工作站和环境条件，并解释缺少的具体条件。
- 树木砍倒后留下树桩，矿脉采空后进入恢复，植物按季节或天气再生。
- 建筑提升周围庇护、安全、温度或加工能力；火光会吸引或驱赶生物。
- 箱子拥有真实容量；背包与箱子支持拖动、拆分、快速转移和快捷栏双向移动。
- 床可保存重生点并恢复；单机睡眠可推进时间，联机必须所有在线玩家同意。

## 5. 世界内交互

- 只有最近、指向或选中的一个目标出现名称和主操作，不给所有资源挂标签。
- 采集包含准备、挥动、命中、受击、碎裂/倒下、掉落、拾取完整反馈链。
- 放置模式保留人物移动、镜头平移与缩放；建造预览显示地基接触、碰撞和有效/无效原因。
- 庇护所、床、火堆、净水器、工作台和箱子都能在世界中直接使用。
- 任务判定监听真实事件，例如拾取、饮用、发现水源、制作和放置，避免“已经拿到淡水但任务不完成”。

## 6. 游戏界面

### 6.1 启动与登录

首次进入显示营地动态背景，主按钮为“建议使用通行证登录”，下方灰色小字为“本地游玩，进度仅保存在本机”。已有存档时，主操作为“继续生存”。公告、下载和设置不与主操作竞争。

### 6.2 常驻 HUD

只保留生命、体力、饥饿、口渴、时间天气、快捷栏和当前情境操作。新任务短暂出现后收入日记。地图默认折叠。日记和背包是次级入口。

### 6.3 完整页面

背包、制作、地图、日记、好友和设置使用完整游戏页面，材质采用旧木、帆布、皮革、黄铜和墨迹。禁止玻璃拟态、SaaS 卡片阵列和大量相同圆角按钮。

### 6.4 更新器

发现 manifest 的版本或 build 高于当前版本时，显示不遮挡游戏的更新提示。展开后显示简介、大小和更新内容；下载进度可收起；完成后调用系统安装器。更新提示不常驻置顶，不删除更新能力。

## 7. 跨端操作

### 7.1 桌面与网页

- WASD 移动；鼠标拖动或边缘移动镜头；滚轮缩放。
- 数字键切换快捷栏；鼠标指向目标执行情境操作。
- 宽屏增加世界可见范围，但 HUD 仍靠近视觉边缘的固定安全区。
- 浏览器触摸模式与桌面模式分离，不以同一组事件阈值兼容全部设备。

### 7.2 手机与平板

- 左拇指移动；拖动空白世界平移镜头；双指缩放。
- 右侧一个随目标变化的主操作键和一个副动作键。
- 五格快捷栏位于底部安全区，可与背包双向拖放。
- 角色约占屏幕高度 8%–10%，附近材料在实际尺寸下可辨认。
- 适配刘海、挖孔、圆角屏、系统状态栏和底部手势区。
- 平板使用独立宽布局，不简单放大手机布局。

### 7.3 联机预留

聊天默认收起，新消息只显示一行预览。好友、邀请和公共岛入口位于暂停页。鸿蒙“碰一下”仅传递好友申请或公共/非个人岛邀请，不传递私人存档。

## 8. 性能分级

提供自动、流畅、均衡、精细四档。所有档位使用相同地图、玩法、资源、配方、实体和存档格式，只调整表现成本。

- 流畅：减少动态阴影、粒子、植被摆动、反射和远景细节。
- 均衡：默认桌面与移动策略。
- 精细：完整光影、植被、天气、水面和更高贴图等级。
- 自动：首次运行评估并在持续掉帧、温度或内存压力出现时提出调整建议；不静默删除内容。

鸿蒙中高配设备默认选择均衡或精细，不预设为兼容档。网页首页和下载中心提供“兼容模式”入口，并标注适合旧手机、集显电脑和低内存设备，同时列出最低与推荐配置。

## 9. 技术组织与数据流

- 物品、配方、生态区、建筑、状态效果、天气和存档结构继续由共享内容层定义。
- 平台渲染层分别使用 Web 世界渲染、Android 原生界面、Apple SpriteKit/SwiftUI、鸿蒙 ArkUI，但消费同一组游戏规则和内容标识。
- 各平台输入统一转为移动、镜头、主操作、副操作、快捷栏、页面开关等语义动作，避免业务逻辑依赖具体按钮。
- 世界更新产生领域事件；任务、日记、音效、动画、掉落、存档和联机同步订阅这些事件。
- 存档采用当前版本、上一份成功存档和迁移版本号；位置、时间、天气、状态、库存、快捷栏、建筑和世界节点状态必须原子落盘。

## 10. 异常与降级

- 存档解析失败时先尝试迁移，再回退上一份成功存档，并向玩家解释而不是直接开新档。
- 资源素材加载失败时使用同类别明确占位并记录错误，不把所有实体替换成同一个图。
- 更新下载中断时支持续传或重新下载；校验文件大小和 SHA-256 后才调用安装器。
- 网络断开不破坏单机存档；联机操作进入可重试状态并防止重复物品或建筑。
- 自动性能调整必须保留人工覆盖，并避免在战斗或建造中突然改变镜头比例。

## 11. 验收与测试

### 视觉验收

- 桌面、常见手机、平板各保留真实运行截图，不以概念图代替。
- 检查角色可见性、实体尺寸差异、遮挡、岸线、水面不可通行和多地形辨识。
- 100%、缩小和放大镜头下，任务、HUD、快捷栏与触控区域保持相对稳定。

### 玩法验收

- 从新档开始能够完成找水、制作斧、制作镐、收集纤维、制作绳索、建箱子、建床和使用庇护所。
- 进食、饮水、睡眠、受伤、恢复、天气和昼夜会正确改变数值。
- 重开各端均回到上次有效进度；设置中的重开必须二次确认。
- 未解锁实体不会提前展示；不同工具、资源和建筑拥有不同逻辑。

### 性能与发布验收

- 低配档验证稳定帧率和内存峰值；精细档验证完整效果。
- Web 桌面和移动浏览器分别测试输入、后台恢复、缩放和缓存迁移。
- Android APK、Apple 构建、鸿蒙 HAP 分别验证包名、版本、build、签名和非调试标记。
- 正式包发布到 `website/api/apps` 后同步 manifest、client-downloads、公开镜像和 `website/api/data/changelogs.json`，下载中心必须实际可见且可下载。

## 12. 非目标

- 不在本次重构中照抄任何现有大游戏的美术、UI 或资产。
- 不用单张宣传图或 WebView 包装替代原生运行体验。
- 不以增加更多常驻按钮代替可玩性。
- 不为了兼容低配设备删减玩法或制作独立的贫瘠地图。
