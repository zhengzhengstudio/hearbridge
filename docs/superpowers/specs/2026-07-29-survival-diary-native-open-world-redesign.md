# 生存日记全端原生开放世界重设计

日期：2026-07-29

状态：产品设计已确认，等待用户规格复核
关联规格：

- `2026-07-26-survival-diary-cross-platform-design.md`
- `2026-07-28-survival-diary-playable-core-and-release-design.md`

本规格记录 2026-07-29 确认的原生化、A/B 游玩模式、开放世界、环境生态、联机和发布要求。凡旧规格仍以 WebView、网页资源套壳或仅交付 Web/Android 为前提的部分，均由本规格取代；旧文档只保留为版本决策历史。

## 1. 目标与完成标准

“生存日记”是一款没有固定结局的开放式海岛生存游戏。玩家能够长期探索、采集、制作、建造、经营、航行、记录和联机，而不是完成几条任务后结束。

项目交付：

- 网页版。
- Android 原生客户端。
- iOS 原生客户端。
- macOS 原生客户端。
- HarmonyOS 联机原生客户端。
- HarmonyOS 单机原生客户端。

全平台正式客户端不得使用 WebView、WKWebView 或 ArkWeb 承载主游戏。旧网页套壳只用于必要的旧存档迁移，不进入新正式架构。

完成必须同时满足：

- 每个平台具有真实可玩的原生游戏主循环，而非静态图片或网页套壳。
- A/B 两种游玩方式可随时切换且共用存档。
- 世界拥有连续昼夜、动态天气、多地形生态和可长期扩展的探索区域。
- 制作结果能成为可放置、可使用、可保存的世界实体。
- 日记本是稳定核心系统。
- 联机、好友、岛屿权限和 HarmonyOS 碰一下遵循本规格。
- 正式安装包、签名、更新清单、下载中心和历史更新日志一致。

## 2. 架构选择

采用“平台原生渲染 + 统一内容与协议 + 跨端一致性测试”，不采用跨平台 WebView，也不以统一网页运行时作为游戏引擎。

### 2.1 平台实现

- Web：TypeScript + Canvas/WebGL。
- Android：Kotlin + Compose/Canvas。
- iOS：SwiftUI + SpriteKit。
- macOS：SwiftUI + SpriteKit，并提供键鼠、大屏和窗口化布局。
- HarmonyOS 联机版：ArkTS + ArkUI/Canvas。
- HarmonyOS 单机版：ArkTS + ArkUI/Canvas，移除联网能力。

各端分别实现渲染、输入、音频、系统权限、通知、下载和安装入口，但共享：

- 地图生成规则与固定种子测试向量。
- 物品、配方、建筑、动物、地形、天气和任务内容数据。
- 存档 schema、迁移规则和校验规则。
- 联机消息、错误码、权限和幂等约定。
- AI 请求/响应结构与本地降级格式。

关键规则使用同一组黄金测试：相同种子和输入事件在各端必须得到一致的库存、天气、时间、建筑、区域生成和任务状态。

### 2.2 现有工程处理

当前 Android `LifeDiary-Android` survival flavor 直接使用 `android.webkit.WebView`；现有 macOS 工程包含 `WKWebView`；现有 HarmonyOS Online 工程包含 ArkWeb，并且若仍属于“生活日记”产品，不得直接改名冒充“生存日记”。

`SurvivalDiaryShared` 可保留内容、schema 和协议资源，但不能视为已完成原生客户端。实施阶段先盘点并隔离“生活日记”与“生存日记”的包名、存档目录、账号配置、签名和下载条目。

## 3. 身份、初次体验与 A/B 模式

### 3.1 默认规则

- 新通行证账号首次登录时默认 A“引导模式”。
- 未登录玩家第一次安装/首次启动时也默认 A。
- 登录玩家的模式选择随账号跨设备同步。
- “本地游玩”玩家的选择只保存在当前设备。
- 切换 A/B 不创建新世界、不重置日记、不改变资源和建造成果。

入口主操作文案为“建议使用铮铮通行证登录”。下方保留“本地游玩”，以灰色小字说明临时身份和存档仅保存在本机。

### 3.2 A：引导模式

引导采用连续自然导语和世界内提示，不使用彼此割裂的大量弹窗：

1. 醒来并观察海岸。
2. 寻找第一份淡水和食物。
3. 制作石斧。
4. 搭建篝火和临时住所。
5. 建造工作台。
6. 探索海岸、内陆和第一处特殊地形。
7. 营地形成后转为长期目标，并提示可切换 B。

玩家始终可以偏离引导。引导只解释选择和风险，不锁定地图、配方或自由建造。

### 3.3 B：自由模式

B 不显示连续任务，只在首次发现、迫近危险或长时间停滞时给出可关闭的轻提示。A/B 开关放在暂停菜单“游玩方式”中，并明确写明“不会重置世界或日记”。

## 4. 无固定结局的核心循环

核心循环为：

1. 探索连续岛屿、海域、洞穴和特殊区域。
2. 采集木材、石料、纤维、食物、水和稀有资源。
3. 通过真实配方制作工具、料理、家具、建筑部件和交通工具。
4. 将制作出的对象拖入世界，预览、旋转并实际放置。
5. 使用、维修、升级或拆除世界实体。
6. 管理饥饿、饮水、体温、精力、淋湿、伤病和天气风险。
7. 发展钓鱼、种植、养殖、烹饪、航行、洞穴探索和好友协作。
8. 将真实经历写入日记，并继续扩展岛屿和营地。

游戏没有最终任务、固定通关画面、四结局或游戏天数上限。长期目标可以完成，但完成后仍可继续探索、建设、经营和联机。

世界采用按区域生成和持久化的群岛结构。已探索区域、玩家建筑和生态变化不会因重新生成而消失；新版本优先向未探索区域增加内容。它不是方块世界，也不复制 Minecraft 的逐方块挖掘规则。

## 5. 真实制作与建造

配方声明输入、产出、制作位置、耗时、工具和解锁条件。制作失败必须列出所缺材料，不能静默扣除资源。

选择可放置物后：

- 半透明实体跟随地面或建筑吸附点。
- 支持移动、旋转、取消和连续建造。
- 绿色状态表示可放置，红色状态说明碰撞、坡度、水深或权限原因。
- 确认后才原子扣除材料并写入世界存档。
- 放置物具备碰撞、耐久、所属玩家/岛屿和交互能力。
- 墙壁、地板和屋顶自动吸附；家具允许自由摆放。
- 世界实体可使用、维修、升级、移动或拆除。
- 未同步的短时间误操作可撤销，但撤销不能复制材料。

所有会改变库存和世界的操作必须先验证再事务提交。断电、崩溃或断线不得留下已扣材料但未生成实体的半成品状态。

## 6. 昼夜、天气与多地形生态

### 6.1 昼夜

时间连续流动，日出、正午、黄昏和夜晚自然过渡。天空、环境光、影子、海面、室内灯光和色温随时间变化。

昼夜影响：

- 夜间能见度和气温。
- 动物行为与资源出现时段。
- 玩家精力和风险。
- 火把、篝火和灯具的照明价值与燃料消耗。

A 模式第一晚自然引导生火和搭建住所；B 模式不强制。

### 6.2 动态天气

天气包含晴、多云、雾、阵雨、暴雨、雷暴、降雪和暴风雪。天气通过云层、风、湿度和声音逐渐过渡，不突然切换背景图片。

天气参与规则：

- 雨水可收集为淡水，也会使人物和物品潮湿。
- 未保护火源可能熄灭。
- 暴雨改变河流水位、海浪和航行风险。
- 雷暴可能击中暴露高物体，避雷设施可降低风险。
- 雾降低视距并改变部分动物活跃度。
- 降雪形成积雪、降低移动速度并提升保暖需求。
- 屋顶、排水、保温和抗风强度具有实际用途。

### 6.3 地形与生态

世界至少支持：

- 沙滩、浅海、珊瑚礁。
- 草地、森林、热带雨林。
- 红树林、沼泽、河流、湖泊。
- 岩石海岸、悬崖和高原。
- 洞穴、地下水域和废弃遗迹。
- 寒冷山地、雪峰和冰湖。
- 火山地带、温泉和熔岩洞。

地形之间使用海拔、温湿度、植被和岩层形成自然过渡带。雪只在高海拔、寒冷岛屿或适合气候中出现。每个生态拥有独立资源、植被、动物、音乐、天气概率和生存策略。

## 7. 2.5D 画面、镜头和自适应 UI

整体视觉为“精细 2.5D 生存世界 + 手绘日记记录”，但世界必须持续动态可操作，不能表现为纯图片游戏。

### 7.1 镜头

- 双指、滚轮和界面按钮均可连续缩放。
- 人物、建筑、动物、资源、阴影和碰撞统一随世界缩放。
- 不为人物和任务目标设置破坏比例的固定最小世界尺寸。
- 任务文字和方向箭头使用屏幕空间 UI，远距离折叠为小标记。
- 支持多角度镜头旋转，并准备相应方向的角色、建筑和工具贴图。
- 放大时显示工具磨损、人物动作、植被摇摆、雨滴和材质状态。
- 缩小时通过 LOD 降低细节，但不让目标与交互点消失。
- 手机和桌面分别保存合适的镜头距离。

### 7.2 HUD

- 顶部只显示时间、天气、温度和必要生存状态。
- 底部为快捷工具栏。
- 手机左侧移动、右侧情境交互/攻击/放置，控件遵循安全区与拇指可达范围。
- 平板和桌面自动扩展快捷栏；macOS 与 Web 支持键鼠、快捷键和边缘滚动。
- 危险状态按需出现，不长期堆满屏幕。
- 日记入口始终稳定可见，但不遮挡游戏主体。
- 所有交互提供按下、不可用、材料不足、保存中、失败和重试状态。

## 8. 贴图与美术规范

游戏物品、工具、资源、食物、建筑和状态采用精细 PNG/WebP 图集，不再以临时 SVG 或表情符号作为最终贴图。

每件可持工具至少具有：

- 背包图标。
- 地面掉落形态。
- 多方向手持形态。
- 使用动作关键帧。
- 正常、潮湿、积雪或损坏等适用状态。

所有资产遵循统一的观察角度、主光方向、接地阴影、轮廓粗细、材质颗粒和颜色范围。基础 UI 符号可以由原生矢量路径绘制，但游戏世界资产必须使用正式贴图或原生渲染对象。

应用图标继续采用“被海水浸旧的深海蓝日记本 + 海岛切口 + 小型罗盘”方向，重新生成高辨识度母版并输出各平台正式尺寸。

## 9. 日记本与 Kimi

日记本是一级核心系统，支持真正翻页，并包含：

- 今日记录。
- 玩家手写日记。
- 地图和地点标注。
- 生物与植物图鉴。
- 制作发现。
- 建造相册。
- 好友来访记录。
- 长期统计和重要回忆。

天气变化、首次生火、新地形、首次制作和好友同行等真实事件生成简短事实记录。玩家可以编辑或删除自己的内容。

日记必须离线可用。Kimi 只在玩家主动选择时提供润色、总结、角色回应或候选叙事；Kimi 超时、限额、断网或无 Key 时，本地规则和日记仍完整工作。AI 不直接发放资源、改变伤害、生成存档结果或替玩家作出关键选择。

## 10. 好友、岛屿权限与联机

### 10.1 好友

- 支持通行证搜索、申请、接受、拒绝、撤回、删除、备注和黑名单。
- 可分别控制在线状态、所在岛屿和可否加入的可见性。
- 好友、最近同行、岛屿成员和邀请记录跨端同步。
- 本地临时身份可单机游玩，但不能建立永久好友或使用云联机。

### 10.2 岛屿权限

岛屿分为个人岛、好友岛、邀请岛和公共岛。岛主可分别授权采集、开箱、使用设备、放置、拆除和邀请他人。

贵重箱、日记本、卧室等默认是私人区域。公共岛和长期共享岛由服务端保存必要世界状态；个人岛默认不允许陌生人进入。

### 10.3 HarmonyOS 碰一下

HarmonyOS 联机版支持：

- 碰一下发送一次性好友申请。
- 碰一下分享公共岛或明确允许邀请的非个人岛。
- 碰一下发送当前联机队伍邀请。

接收方必须先看到发送者、岛屿名称、权限和有效期，再明确确认。令牌随机、单次使用且短时过期，不携带密码、私钥、完整存档或 Kimi Key，也不能绕过黑名单和岛屿权限。

其他平台提供二维码、邀请链接和短邀请码作为等价入口。HarmonyOS 单机版不包含好友、聊天、公共岛、网络邀请和碰一下能力。

### 10.4 同步与断线

移动、采集、库存、建造、天气和时间由服务器权威校验。客户端操作带唯一事件编号，重复提交不得产生双份资源。

短时断线保留本地操作队列并重连校验；冲突时显示选择或回滚原因，不能静默覆盖。单机存档登录后由玩家主动选择上传为新岛，不自动覆盖云端岛屿。

## 11. 存档、隐私与迁移

存档至少包含：

- `schemaVersion`、产品版本和构建号。
- 世界种子、区域快照和事件日志尾部。
- A/B 模式及其提示设置。
- 库存、配方、放置实体、日记、发现和好友权限引用。
- 时间、天气、生态状态和校验值。

本地存档使用原子写入并保留最近可恢复快照。旧 WebView 存档迁移遵循“先备份、只补字段、不扣资源、不改变已建坐标、不覆盖日记”。迁移失败时保留原始数据并提供明确恢复路径。

通行证云同步只传输实现同步所需的数据。日记默认私人；好友可见和公开可见分别由玩家主动开启。

## 12. 版本检测、下载与合规安装

统一 manifest 负责版本检测。存在更新的条件为远端语义版本更高，或版本相同但远端整数 build/versionCode 更高。

清单至少包含：

- 平台、渠道、架构和单双机标识。
- `version`、`build`、最低兼容存档版本。
- 文件 URL、大小、SHA-256、签名身份和发布时间。
- 更新说明、是否强制和商店跳转地址。

下载必须支持重试/断点续传并在安装前校验文件、包名和签名。强制更新仅用于严重安全问题或存档/网络协议不兼容。

平台行为：

- Android 网站分发版：下载正式签名 APK 到系统 Downloads，校验后通过 `PackageInstaller` 让用户确认。Google Play 版仅走 Play 更新，不申请不符合政策的站外自更新权限。
- iOS：manifest 可提示更新，但正式用户通过 App Store/TestFlight 等合规渠道安装；普通 App 不下载任意 IPA 并调用系统安装器。
- macOS 网站分发版：下载 Developer ID 签名并完成 Apple 公证的 DMG/PKG，校验后打开系统安装流程；Mac App Store 版走商店更新。
- HarmonyOS 市场版：应用内检测并提示，随后进入应用市场升级；测试或其他合规渠道使用该渠道允许的正式签名安装方式。
- Web：Service Worker 或资源版本机制提示刷新，并在更新前保存当前游戏状态。

参考官方规则：

- Android `REQUEST_INSTALL_PACKAGES` 政策：<https://support.google.com/googleplay/android-developer/answer/12085295?hl=en-GB>
- Apple App Store Connect 构建分发：<https://developer.apple.com/help/app-store-connect/manage-builds/upload-builds/>
- Apple Developer ID 与 macOS 公证：<https://developer.apple.com/support/developer-id/>
- HarmonyOS 应用安装与更新：<https://developer.huawei.com/consumer/cn/doc/doccenter-getting-started/application-package-install-uninstall>

## 13. 正式签名与产物

- Android 使用独立 release keystore，保存在 `/Users/ljg/Desktop/开发者/TRAE/Android证书` 的受保护位置；密码不得进入源码、日志或 Git。
- iOS 使用有效 Apple Distribution 证书、对应 Bundle ID 和 provisioning profile。
- macOS 网站分发使用 Developer ID Application；PKG 使用 Developer ID Installer，并启用 hardened runtime、完成 notarization 和 stapling。
- HarmonyOS 使用正式发布证书、Profile 和对应应用身份签署 APP/HAP。
- 单机版和联机版分别构建并清晰区分应用身份、能力和下载条目。
- 后续覆盖升级必须维持包名/应用身份和签名连续性。

缺少发布账号、私钥或 Profile 时，只能标记为“可签名工程/未签名构建”，不得冒充正式签名或 `storeReady`。

正式产物放入 `website/api/apps`。发布采用临时文件校验后原子替换，避免下载中心在上传一半时暴露新版本。

## 14. 下载中心、manifest 与更新日志

每次正式发布必须同步更新：

- `website/api/apps/manifest.json`。
- `website/api/apps/client-downloads.json`。
- 主站实际读取的 manifest/client-downloads 镜像或生成产物。
- `website/api/data/changelogs.json` 及主站实际读取的更新日志镜像。

下载中心条目显示图标、真实游戏截图、简介、平台、渠道、单双机、版本、build、大小、校验值、发布日期和安装方式。根据访问设备优先显示对应平台，但允许查看其他平台。

历史遗漏更新根据已有包、旧 manifest、文件校验、提交历史和现有文档补齐。无法验证的日期、版本内容或签名状态不得猜测。没有实际可下载产物的条目不能显示为可用。

按照工作区 `AGENTS.md` 约定，后续对 `website` 的非敏感产品更改同步写入 `api/data` 更新日志。

## 15. 商店与比赛素材

HarmonyOS 单机版商店素材包括：

- 1024 × 1024 正式图标。

比赛视频必须以真实可运行画面展示连续操作：首次进入 A 引导、探索多地形、昼夜/天气变化、制作与放置、日记、好友联机和 HarmonyOS 碰一下。宣传镜头不能替代真实玩法证明。

## 16. 测试与验收

### 16.1 自动测试

- A/B 默认值、切换、账号同步、本地保存和共用存档。
- 固定种子的地形、昼夜、天气和跨端规则一致性。

- 好友申请、黑名单、岛屿权限、碰一下令牌和重复事件幂等。
- 断线重连、云冲突、旧 WebView 存档迁移和损坏恢复。
- 手机、平板和桌面 HUD；缩放、旋转、LOD 与屏幕空间标记。

### 16.2 手工验收

新玩家在手机上应能连续完成：首次进入默认 A → 观察海岸 → 找水与食物 → 制作石斧 → 搭建篝火和住所 → 遇到夜晚/天气变化 → 建造工作台 → 打开日记 → 缩放和旋转地图 → 切换 B → 确认世界、库存和日记完全保留。

联机验收包括：申请好友 → 邀请进入允许的岛屿 → 共同采集与建造 → 断线重连 → 权限阻止未授权拆除。HarmonyOS 真机额外验证碰一下申请、邀请信息预览、确认、过期令牌和黑名单拒绝。

发布验收包括：安装首个正式签名版本 → 收到更高 build 提示 → 校验并进入平台允许的安装/商店流程 → 覆盖升级后存档保留 → 下载中心显示且实际文件可完整下载。

## 17. 实施边界与顺序

本规格确认的是产品和技术方向，不表示现有 WebView 包已经完成原生化。正式实施计划应按以下依赖拆分：

1. 隔离产品身份并固化共享 schema、内容格式、协议和黄金测试。
2. 建立各平台原生最小可玩客户端与存档迁移入口。
3. 完成 A/B 引导、核心生存循环、真实建造、日记和环境系统。
4. 完成精细贴图、镜头、缩放、旋转和全尺寸自适应。
5. 接入通行证、好友、岛屿权限、云存档和联机。
6. 完成 HarmonyOS 碰一下及其他平台邀请降级路径。
7. 完成更新检测、正式签名、平台合规安装和全端安装包。
8. 原子发布到下载中心，补齐历史更新日志。
9. 生成并核验鸿蒙商店与 B 站比赛素材。

进入代码实施前，必须先由用户复核本规格，然后基于本规格重新编写实施计划；旧的“Canvas 网页 + Android WebView v0.2”计划不得继续作为全端目标执行。
