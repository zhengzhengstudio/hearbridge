## 🔥 WorkBuddy 沙箱 broker-shim 拦截原生构建（关键发现）
在 WorkBuddy 沙箱里跑任何外部 Node 工具（DevEco hvigor、Cocos gradle/java、Android Studio 等）时，
环境会注入一组变量，把进程的文件写入/子进程全部路由到 broker IPC，导致原生构建卡死/超时：
- `NODE_OPTIONS=--require=".../node-language-shim.cjs"`（注入 broker fs hook）
- `ELECTRON_RUN_AS_NODE=1`、`CODEBUDDY_BROKERED_FS_HOOK_ENABLED=1`、`SANDBOX_CENTER_IPC_ADDRESS=...`
- `BASH_ENV=.../shell-runtime-bash-env.sh`（子 shell 再次 source broker 环境）

**现象**：hvigor 编译全部 Finished，但 log4js 写 build.log 时抛 `CODEBUDDY_BROKER_TIMEOUT`
（`Broker request timed out`），整个构建挂死（之前 SpaceFight 鸿蒙 HAP 在 CacheNativeLibs 卡 4 分钟就是它）。
Cocos / Android gradle 同理会被拦截。

**修复（对所有原生构建通用）**：启动外部工具时用 `env -u` 摘掉这些变量即可直连文件系统：
```
env -u NODE_OPTIONS -u ELECTRON_RUN_AS_NODE -u CODEBUDDY_BROKERED_FS_HOOK_ENABLED \
    -u SANDBOX_CENTER_IPC_ADDRESS -u BASH_ENV -u CODEBUDDY_BROKERED_SHELL_ENV \
    -u CODEBUDDY_SAFE_DELETE_SANDBOX -u CODEBUDDY_BROKERED_BIN_DIR <外部命令>
```
（`dangerouslyDisableSandbox:true` 不够——它不摘 NODE_OPTIONS，hvigor 仍走 broker 超时；
必须显式 `-u` 这些变量才行。）
