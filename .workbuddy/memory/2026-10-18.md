## 🚨 验证 website 站点：8114 是假通，沙箱有代理
**坑 1：8114 是 catch-all 假通**。任何不存在的路径（含 `__not_exist__`）都返回 **200 + "铮铮眼镜"页**。
→ **绝不能只看状态码**，必须 `grep -oE "<title>[^<]*</title>"` 比对内容指纹。
我一度把 8114 误报成"荔枝页通了"，用户差点拿到错信息。

**坑 2：沙箱有 `HTTP_PROXY=127.0.0.1:63197`**，curl 默认走代理 → 全部返回 **502 upstream connect failed**，
看起来像"服务没起来"，其实是代理拦截。加 `--noproxy '*'` 立刻正常：
```bash
curl -s --noproxy '*' -H "Host: zheng-homework.zhengzhengstudio.cn" http://127.0.0.1:8110/...
```

**站点按 Host 头分发**（server.js:2023）：`zheng-homework.zhengzhengstudio.cn` → 站点根目录。
不带正确 Host 头一律 404。判断"页面是否真的存在"必须三件套：
`--noproxy '*'` + `-H "Host: zheng-homework.zhengzhengstudio.cn"` + 比对 `<title>`。

**启动服务别加 `| head -N`**：管道写满 N 行后 SIGPIPE 会把服务打死（我踩过，日志里先正常后 502）。
用 `run_in_background` 不加管道，或 `| tee logfile`。默认端口 8110（`PORT=8110 node server.js`）。
