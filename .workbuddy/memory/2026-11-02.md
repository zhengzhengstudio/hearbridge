## SpaceFight 原生端 bug 排查（用户反馈：无法返航/画面扭曲/血条没了/贴图）
- **根因定位**：`ExpeditionDirector.canReturn()`（assets/scripts/core/ExpeditionDirector.ts:98-103）现返回
  `phase !== 'failed' && phase !== 'complete'`，注释明确说这是修复「开局 primary 阶段无法返航/卡死」的改动。
  → 当前 TS 源码已修，但**线上 web/安卓/鸿蒙构建是旧构建（改前编译）**，所以用户测到的 App 仍「无法返航」。
- **返航按钮**：`NativeCombatHud.ensureReturnAction` 仅在 `canReturn||canDock` 时显示节点；修复后全程可显。
  原生是「按住持续 + 受击中断」机制（HUD 已写提示文案）。按钮可见但「按了没反应」的可能原因：原生触摸命中
  映射或 `returnRequested` 输入未接通，需真机验证。
- **画面扭曲·网页**：已热修。部署的 `index.html` 仍 `cc_exact_fit_screen="true"`（BrowserWindow=拉伸），
  模板与部署 CSS 已是 `false` + `object-fit:contain`。已把部署 index.html 改为 `false` 并 sync 到 Termux（success）。
  注意：HTML 无缓存，硬刷新即生效。
- **画面扭曲·原生**：原生无 HTML/CSS，扭曲来自 Cocos **resolution policy**（design 1280×720 vs 设备宽高比）。
  拉伸(NO_BORDERS)=扭曲；FIT/SHOW_ALL=letterbox。此设置在构建/运行时，不在我改的 TS 里 → 需原生重建并核对策略。
- **血条没了·原生**：`hullStatusBar` 在 `createStatus→layoutStatus` + 每帧 `syncCombat` 重绘，理论上恒显。
  「没了」最可能是旧构建坐标/画布适配问题或 HUD canvas 适配把元素推到可视区外 → 需重建+真机验证。
- **贴图**：线上 Termux 有真实 PNG（正常）；本地 Mac 看到破贴图是 iCloud 占位符 `.icloud` 导致，非线上 bug。
