## 第二轮：眼镜上架网站（14:00 前后）

### 核心结论：上架不只是"同步文件"
眼镜**下载走 `zhengzhengstudio.cn/api/apps/`**（`website/api/server.js` 第 79 行 express.static 挂载），
**不是**根 `website/api/apps/`。两份 manifest 都要改，但真正被下载的那份是 `zhengzhengstudio.cn/api/apps/`。

### 🚨 build.json 是 `--glasses-apps` 的派包来源，不更新就同步旧包
`sync_to_termux.js` 的 `syncZhengZhengGlassesApps()` 读 `ZhengZhengGlasses-build.json`
的 `packages[].fileName/latestFileName` 决定传哪些包。
本轮 build.json 还是旧值（macOS→`v0.1.5.dmg`、HarmonyOS→`v1.0.2-signed.hap`），
**必须先改 build.json 再跑 `--glasses-apps`**，否则同步的是旧 dmg/旧签名 hap，manifest 却指向新文件 → 线上 404。
已改：macOS→`v0.1.6.zip`、HarmonyOS→`v1.0.2-unsigned.hap`（两份 build.json 同步改，sha/size 一致）。

### 🚨 文件同步 ≠ 服务重启（自己远程做，不用麻烦 yy）
Termux 上有 admin 命令端点 `POST /api/admin/termux/command`（需 `x-admin-username` + HMAC-SHA256 token，
key 默认 `H3CXiangshan=`，脚本 `signAdminToken()`）。可远程执行任意 shell → **pm2 restart 我自己能做**。
- 8110 = pm2 进程 **`zhengzheng-api`**（`website/api/server.js`）。
  它 require 眼镜路由：`path.join(__dirname,'../zhengzhengstudio.cn/server/routes/glasses')`（server.js:97），
  挂载 `/api/glasses`（:173）。**眼镜路由文件在 `zhengzhengstudio.cn/server/routes/`，不在 `website/api/`**。
- 眼镜**静态站**是独立服务 `zhengzheng-glasses`（`website/api/glasses_server.js`），
  监听 **8114**(HTTP)/8116(HTTPS)，静态根 `website/glasses.zhengzhengstudio.cn`。
  ⇒ 8114 任何路径都回 index.html（catch-all），**判活必须比对 title 指纹**：
  正确是「铮铮眼镜 - 我的试戴主页」，主站是「铮铮实验室 - ZhengZheng Studio」。
- `pm2 restart` 时 HTTP 响应报 `ERR socket hang up` 是**正常的**（自己重启自己，连接被断）。
- 传单个文件可绕过 sync 脚本：`POST /api/internal/sync-file`，header `X-Sync-Secret: zhengzheng_sync_secret_2026`，
  body `{relativePath, content(base64), encoding:'base64', secret}`。

### 本轮上架验证结果（全部实测，非"日志说成功"）

  `macOS-v0.1.6.zip`、`HarmonyOS-latest.hap`=258569/`609f22d0…`、`HarmonyOS-v1.0.2-unsigned.hap` 全一致 ✅
- 线上 manifest：macOS v0.1.6 b7 / harmonyos v1.0.2 b10002（标题已改 unsigned）/ android v0.1.17 b18 ✅

### 全量同步最终结果与补传
- 全量同步耗时 24 分钟，**3206 成功 / 41 失败**。
- 41 个失败**全是我自己的锅**：同步途中执行了 `pm2 restart zhengzheng-api`，
  8110 短暂断开 → 后续大包分块上传 ECONNREFUSED。失败清单是桌游/battery-organizer
  的历史 apk/hap，**眼镜 2077 个文件 0 失败**（latest 别名也没失败）。
- 补传用分块端点 `/api/internal/sync-file-chunk`（body 含 `uploadId`=sha256(路径:大小:mtime) 前 24 位），
  **41/41 成功**，每个都回读线上 content-length 与本地 size 比对。

### 🚨 坑：远端 relativePath 前缀 ≠ 公开 URL（回读校验会假 404）
上传时远端相对路径是 `zhengzhengstudio.cn/api/apps/xxx.apk`（含站点目录前缀），
但**公开 URL 不含该前缀**，是 `/api/apps/xxx.apk`。
我一开始按 `'/' + relativePath` 回读 → 全部 404（那 204~224 字节是错误页大小，不是包大小），
误判成"补传失败"。实际上传早就 200 成功了。
⇒ **回读校验前先剥掉站点前缀**：
```js
const publicPath = '/' + relativePath.replace(/^zhengzhengstudio\.cn\//, '');
```

### 🚨 同步途中不要重启 pm2（会打断正在上传的包）
`pm2 restart` 会让 8110 短暂不可用，正在传的大包分块会连不上 →
整批失败且不会自动补。要重启就**先等同步结束**，或接受失败后手动补传。

### 🚨 关键发现：旧 Android apk 直接吃修好的服务端目录，不用等新包

- 下载线上 v0.1.17 apk 解包，`strings` 扫 dex 得出它引用的目录字段只有
  `frames / image / lensWidth / bridgeSize / merchantId / thumb`；

  （30 个，含上面 6 个 + `tryOnImage/thumb/lensWidth/bridgeSize/…`）**完全覆盖**；
- Android 端 `fetchCatalog()` 解析 `data.optJSONArray("frames")`，frames 非空即用。
⇒ **v0.1.17 装上就能看到 318 款真实镜框**（此前只有 2 条占位）。
新增字段对旧 apk 无副作用；旧映射里的 `imageCorrection`/`overlayScale` 新数据没有，
Android 侧用 `opt*` 读取不会崩。

### Android 源码现状（别看错）
- 工作区源码是 **Java**：`NativeMainActivity.java`（1728 行/88KB，含 catalogPage/showCatalogPage/addAllFrames 等分页逻辑 8 处）

  要还原 v0.1.17 级别，得先找回 Kotlin 源码。
- 本地 `ZhengZhengGlasses-Android-v0.1.13.apk` / `v0.1.17.apk` **真身不存在**（只有 `.icloud` 占位符）。
