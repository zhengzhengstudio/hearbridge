## SpaceFight 0.13.6 安卓「飞不了 + 前哨站模型消失」根因与修复
- **症状**（用户报于已发布的安卓 APK 0.13.6 / build 70）：整个画面冻住、飞船/敌人/子弹全停但没显示「已暂停」、
  前哨站 3D 模型不显示（被 2D 面板盖住）。
- **根因**：远征完成后 `expedition.phase='complete'` → `mission.status='complete'`。
  `CombatBootstrap.update()` 每帧因该状态自动 `enterOutpost()` → `docked=true` → `step()` 早退（整屏冻）。
  玩家点「离港」调 `departOutpost()`，旧代码**只置 `docked=false` 却不把 `phase` 从 `complete` 复位**，
  下一帧 Bootstrap 又自动入港 → 无限再入港循环，飞船被永久钉在前哨站。
  网页端因 `enterOutpost` 设 `pausedByLaunchGate=true` 把循环掩盖成「暂停」，仅安卓原生端（不设该标志）
  直接暴露成整屏冻结。0.13.6 的碰撞半径 15 停靠修复解锁了「能靠近前哨站」，才让此 bug 暴露。
- **修复**（`SpaceFight-Cocos/assets/scripts/core/CombatSimulation.ts` 的 `departOutpost()`）：
  离港时重建一份新的 `primary` 阶段远征（新 seed），并清 `primaryCompleted`/`decisionElapsed`。
  同时把字段 `private readonly expedition` 改为 `private expedition`（允许重新赋值）。
- **回归测试**：`tests/spacefight_cocos_simulation.test.js` 新增一条，把远征推进到 complete → 断言
  `departOutpost()` 后 `mission.status !== 'complete'`、`expedition.phase==='primary'`、飞船能继续飞（位置变化）、
  `navigation.docked` 保持 false（不会再次被钉进前哨站）。
- **验证**：`test:simulation` 60/60、`test:contract` 5/5、`test:all` 全绿（修复仅动核心逻辑 + 字段修饰符）。
- **待决**：是否要据此出 **0.13.7 / build 71** 安卓包重发（原生重导 → 瘦身 → gradle 重签 → stamp/upload/finalize/sync → 重启 pm2）。
  源码修复已就绪，发布需 yy 拍板（涉及线上版本号 bump + 远端同步 + 重启服务）。

## SpaceFight 安卓「开局点 Deploy 即冻结」独立 bug（区别于 0.13.7 的再入港循环）
- **现象澄清**（yy）：不是完成远征后的再入港循环，而是**刚点主页 Deploy 起飞第一秒，飞船和敌人就都不动**（开局即冻结）。
- **根因**：`CombatBootstrap.update()` 有 `!isPlayerVisualReady()` 早退闸；原生端 `ShipPresenter.initialize()` 故意跳过 fallback 视觉创建（防首帧前建运行时网格让部分 Android GPU 驱动崩溃），且 `ensurePlayerVisual()` 的 fallback 分支只打日志不建节点 → **玩家模型一旦在设备侧加载失败/挂起/超时，`playerVisual` 永为 null → `isPlayerVisualReady()` 恒 false → 开局永久冻结**。已证 0.13.6 APK 包内 `models-low/ships/interceptor` 模型齐全，故非缺模型，而是「原生端无兜底」。
- **修复**（已落盘，待出包）：
  - `CombatBootstrap.ts`：新增 `combatVisualWaitMs`；`update()` 视觉闸改为 **5s `PLAYER_VISUAL_GRACE_MS` 宽限**（宽限内只 sync 不推进，超时后调 `ensureFallbackVisual()` 用低模兜底继续推进）；`leaveOutpost()`（部署开局）重置 `combatVisualWaitMs=0`。
  - `ShipPresenter.ts`：新增 `ensureFallbackVisual()`（首帧后建 box fallback 机体并置 `playerVisual`）+ `fallbackVisualAttempted` 守卫（只尝试一次）。
- **验证**：`test:simulation` 60/60、`spacefight_ship_device_contract.test.js` 11/11 全绿。新增回归护栏：断言 `ensureFallbackVisual`/`fallbackVisualAttempted`/`PLAYER_VISUAL_GRACE_MS`/`combatVisualWaitMs = 0` 代码路径存在。
- **版本盖章补全**：发现 0.13.7 发布时只 bump 了 `package.json`(0.13.7/71)，`settings/v2/packages/project.json` 与 `build-templates/web-{desktop,mobile}/index.ejs` 仍残留 0.13.6/BUILD 70，导致 contract 测试「Cocos 元数据不得漂移」失败。现已补齐这三者到 **0.13.7/71**（与已发布状态一致）。
- **待 yy 拍板**：本修复需新版本出包/发布（安卓重导 → prune → gradlew 重签 → 盖章 4 清单 → 分块上传 → 核验）。建议 bump 到 **0.13.8 / build 72**（或 0.13.7 重建 build 72），届时须同步 bump `package.json`+`project.json`+两份 ejs 一致。
