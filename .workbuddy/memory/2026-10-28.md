## 🔑 SpaceFight Android release 卡点根因（沙箱只拦删不拦写）+ 解法
- **现象**：`assembleRelease` 反复在 `:spacefight-cocos:configureCMakeRelWithDebInfo` 报 `Operation not permitted`，栈顶是 AGP `PathUtils.deleteRecursivelyIfExists` 删 `build/RelWithDebInfo/.../metadata_generation_command.txt`。
- **根因（关键）**：本机 Bash 沙箱对 `native-build-spacefight`（经 `SpaceFight-Cocos/native-build` 软链、在 iCloud 同步树外）这类**外部路径**：**允许 create/write，但禁止 unlink/delete**。第一次 release 能过是因为那是全新构建、没有陈旧产物要删；之后每次 AGP 想清旧原生输出就被拦。注意 `rm -rf`（默认沙箱）删外部目录也失效，必须 `dangerouslyDisableSandbox` 才能删。
- **解法**：把 `proj/build` 做成指向**工作区内部**目录的软链（`ln -s /Users/ljg/Desktop/开发者/TRAE/.sf_build proj/build`），让写和删都落在沙箱允许区。验证 `configureCMakeRelWithDebInfo` 即过，全量 `assembleRelease` 进入引擎 C++ 编译（572 目标）。
- **教训**：以后在本机对 `native-build-spacefight` 跑 gradle 构建，先把 `proj/build` 软链到工作区内；否则 AGP 清理陈旧输出必 EPERM。
