### 构建四道坎
1. `ELECTRON_RUN_AS_NODE=1` 让 Cocos 的 Electron 当纯 Node 跑 → `bad option: --project`
   解法：`env -u ELECTRON_RUN_AS_NODE -u NODE_OPTIONS -u NODE_PATH -u NODE_EXTRA_CA_CERTS`
2. GPU 进程崩溃 → wrapper 用 `--use-gl=swiftshader --use-angle=swiftshader
   --enable-unsafe-swiftshader --no-sandbox`
   ⚠️ 先试的 `--disable-gpu --disable-software-rasterizer` 会让 Cocos 无法输出 GL
3. Java 8 → AGP 8.10.1 要11+ → 用 Android Studio 自带 JBR 21
4. gradle 不传 `-PNATIVE_DIR` → `proj/app` 不存在；不传签名参数 → 不签名

### 最隐蔽的一个坑
`R.drawable.spacefight_launcher_keyart` 找不到符号，gradle **不报错**，
只在 `compileReleaseJavaWithJavac` 报。查 `R.txt` 只有 9 行才发现资源没被收录。
根因：`app/build.gradle` 的 `res.srcDirs 'res'` 相对 projectDir（Cocos 指向 `proj/`），
所以图必须放 `native/engine/android/app/res/drawable-nodpi/`，
放 `native/engine/android/res/` **完全无效**（不报错、不生效）。

### 踩坑记录（下次直接照抄）
- **线上 keyart 不在 `/resources/ui/launcher/` 下**（404）。Cocos 打包后按 uuid 落盘：
  `assets/resources/native/<uuid前2位>/<uuid>.<hash>.png`。要先从 `cc.config.*.json`
  里 `["ui/launcher/spacefight-launcher-keyart",4,1]` 拿到 index，再由 uuid 反查。
- **APK 内是双层 `assets/assets/…`**（不是单层），用 `unzip -l | grep` 先定位再 `-p | md5`。
- **Cocos 源码 `.png` 与打包产物 `.png` 字节完全相同**（未压缩重编码），
  所以 md5 可直接跨层比对，这是最快的版本判定手段。
- git 快照 `4752d91a` 里同时存在 `spacefight_launcher_keyart.png` 和
  `spacefight_launcher_keyart 2.png`（iCloud 冲突副本），内容一致，可互为备份。
- `assets/resources/ui/launcher/` 下还有一个占位符
  `.spacefight-launcher-keyart 3.png.icloud`（184B）尚未物化，
  但已有上面 5 份一致副本，无需再下载。
- ⚠️ `/tmp` 在两次 Bash 调用之间会被隔离/清空，临时产物要放
